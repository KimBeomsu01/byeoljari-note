## 1. 목적과 핵심 원칙

별님(시설 이용 장애인)의 체온과 하루 관찰 기록을 근무 교대 때 다음 선생님에게 빠짐없이 넘긴다. 담임이 바뀌어도 기록은 별님 단위로 이어진다.

| # | 원칙 | 상태 |
|---|---|---|
| P1 | **확인** = 읽었다 / **완료** = 처리했다. 두 상태를 섞지 않는다 | [확정] |
| P2 | **긴급**(고온·저온)은 어떤 필터를 골라도 최신 기록 맨 위에 보인다 | [확정] |
| P3 | 확인 상태는 기록 하나에 하나만 있다. 최신 기록에서 누르든 아카이브에서 누르든 같은 상태가 바뀐다 | [확정] |
| P4 | 모든 기록은 별님 아카이브에 쌓인다. 반 공지는 그 반 별님 전원의 아카이브에 들어간다 | [확정] |
| P5 | 아카이브를 **열기만** 해서는 확인 처리하지 않는다. 사용자가 직접 눌러야 한다 | [확정] |

## 2. 용어

| 용어 | 정의 |
|---|---|
| 별님 | 시설 이용자. 하나의 반에 속한다 |
| 반 | 생활 단위. 예: 물병자리, 은하수자리. 반마다 담임이 있다 |
| 선생님 | 앱 사용자(직원). 근무조에 배정된다 |
| 사무국 | 전체 공지를 쓰는 행정 담당(행복지원팀) |
| 근무조(Shift) | 같은 시간대에 근무하는 선생님 묶음. 예: 오전 근무 · 선생님 4명 |
| 기록(Entry) | 인수인계에 올라가는 단위. 전체 공지 / 반 공지 / 별님 기록 |
| 할 일(Task) | 기록에 붙는 처리 항목. [완료하기]로 닫는다 |
| 긴급(Alert) | 고온·저온 체온 기록에 붙는 상태. 재측정으로 해제한다 |
| 확인(Read) | 해당 선생님이 기록을 읽었다는 표시 |
| 답글(Reply) | 기록에 다는 짧은 댓글 |

## 3. 화면 구성

```
인수인계 탭
├─ [세그먼트] 최신 기록 (미확인 수 배지) | 별님별 기록
├─ 최신 기록
│   ├─ 교대 요약 카드
│   ├─ 필터 칩: 모두 · 미확인 · 할 일 · 전체 공지 · 반별 공지 · 별님 기록
│   ├─ 긴급 섹션 (열린 긴급이 있을 때만)
│   ├─ 고정된 전체 공지 ("모두" 필터에서만)
│   └─ 최신 기록 목록 (반 공지 + 별님 기록, 시간 역순)
├─ 별님별 기록
│   ├─ 반 탭 (반별 미확인 수)
│   └─ 별님 그리드 (3열)
├─ 별님 아카이브 (그리드나 카드의 별님 이름에서 진입)
│   ├─ 별님 프로필 + [별님카드 ›]
│   ├─ 필터: 모두 · 이 별님 기록 · 반 공지
│   └─ 날짜별 타임라인 (+ 여기까지 읽음 선, 담임 변경 구분선)
├─ FAB: 관찰 기록 남기기 (아카이브에서는 "○○ 별님 기록 남기기")
├─ 시트: 관찰 기록 작성
└─ 시트: 체온 입력 (재측정·할 일 완료용)
```

### 3.1 최신 기록

#### 교대 요약 카드
| 항목 | 정의 | 누르면 |
|---|---|---|
| 긴급 | 상태가 열림인 긴급 수 | "모두" 필터로 바꾸고 첫 긴급 카드로 스크롤 |
| 남은 할 일 | 완료되지 않은 할 일 수 (작성자 무관) | "할 일" 필터 |
| 안 본 기록 | 3.1 범위 안에서 4.3 미확인 정의에 해당하는 기록 수 (긴급 제외) | "미확인" 필터 |
| 체온 미기록 | 현재 근무조 측정 시점에 체온이 없는 별님 수. **체온 모듈에서 받는 값** | 체온 탭으로 이동 [TBD: 이동 방식] |

- 긴급, 할 일, 안 본 기록이 모두 0이면 "넘겨받을 일을 모두 확인했어요" 상태로 바꾼다.
- 헤더 문구: "{근무조명} 인계 · {기준시각} 기준 · {반 수}개 반 {별님 수}명"
- 프로토타입의 "체온 미기록 3"은 고정 더미값이다. 실제로는 체온 모듈과 연동해야 한다.

#### 필터
| 칩 | 보이는 기록 | 정렬 |
|---|---|---|
| 모두 | 고정 전체 공지 → 나머지 | 각 묶음 안에서 최신순 |
| 미확인 | 미확인 기록 전체 (공지 포함) | 전체 공지 먼저, 그다음 최신순 |
| 할 일 | 할 일이 붙은 기록 | 열린 것 먼저, 그다음 최신순 |
| 전체 공지 / 반별 공지 / 별님 기록 | scope가 같은 기록 | 최신순 |

- 모든 필터에서 긴급 섹션이 목록 위에 붙는다 (P2). 섹션 제목: "긴급 n · 어떤 필터에서도 맨 위"
- 칩 옆 숫자는 해당 필터의 기록 수다. 미확인 칩만 "남은 수"를 뜻한다.
- 필터를 바꾸면 스크롤이 맨 위로 돌아간다.
- **보여주는 범위** [확정: 방식 C]
  1. **기록**: **내 직전 근무의 시작 시각 이후** 생긴 기록. 기준 시각은 선생님마다 다르다.
     - 예: 어제 오전 근무 후 오늘 출근 → 어제 오전부터 / 사흘 쉬고 출근 → 사흘 전 근무부터
     - 직전 근무 기록이 없는 경우(신규 직원 등): 최근 24시간 [가정]
  2. **열린 할 일**: 생긴 시점과 상관없이 **완료될 때까지 계속** 보인다.
  3. **고정 전체 공지**: 기간과 상관없이 보인다 (만료 규칙은 4.5).
  - 범위 밖의 기록은 별님 아카이브에서 본다.
- **"모두" 목록 순서**: 긴급 → 고정 전체 공지 → **이전 근무에서 넘어온 할 일**(범위 밖에서 들어온 열린 할 일만, 있을 때만 섹션 표시) → 최신 기록
- 목록 끝 문구: "✦ 내 지난 근무({날짜} {근무명})부터 모아 보여요 / 그 전 기록은 별님 아카이브에서 볼 수 있어요"
- **빈 상태**
  - 미확인: "안 본 기록이 없어요. 모두 확인했어요."
  - 할 일: "남은 할 일이 없어요."
  - 그 밖의 필터: "기록이 없어요."

#### 기록 카드 (공통)
- 상단 라벨
  - 전체 공지: "전체 공지 · 위에 고정"
  - 반 공지: "{반} 반 공지 · 반 전원 아카이브에 기록"
- 작성자 아바타, 이름, 기록 종류, 시각
- 별님 기록에는 별님 칩(아바타 · 이름 · 반 · ›)이 붙고, 누르면 별님 아카이브로 간다.
- 본문 영역: 체온 박스(값, 판정, 부가 설명) / 제목 / 본문 / 사진 / 할 일 박스
- 하단 영역
  - 확인한 사람 아바타(최대 4, 열린 할 일 카드는 2)와 "확인 n/{근무조 인원}"
  - [답글 n]
  - 버튼
    - 남이 쓴 기록: [확인] ↔ [✓ 확인함] 토글
    - 열린 할 일: [확인] + [완료하기]. 내가 쓴 기록이면 [완료하기]만
    - 내가 쓴 기록(할 일 없음): "내가 남긴 기록" 텍스트
- 전체 공지는 내가 이미 확인한 상태로 화면에 들어오면 본문을 접는다. 단, "전체 공지" 필터에서는 펼친다.
- 이번 세션에서 새로 쓴 기록은 테두리를 강조한다.

#### 긴급 카드
- 라벨: "● 긴급 · {고온|저온} {값}°"
- 별님 아바타, 이름, 반, 측정한 선생님, 측정 시각
- 진행 단계
  1. ✓ {시각} 간호 담당 선생님께 알림 (자동)
  2. (재측정했는데 아직 범위 밖이면) ✓ {시각} 재측정 {값}° · 아직 {판정} ({측정자})
  3. ⏱ {예정 시각} 재측정 예정 · 30분 뒤
- 하단: 확인, 답글, [재측정 입력]

### 3.2 별님별 기록
- **반 탭**: 반 색 점, 반 이름, 미확인 수 배지(0이면 숨김). 선택된 탭이 보이도록 가로 스크롤을 맞춘다.
  - 미확인 수 = 그 반의 반 공지와 별님 기록 중 내가 확인하지 않은 것 (긴급 제외)
  - 기본 선택 반: [TBD] 내 담당 반 / 마지막으로 본 반 (프로토타입은 은하수자리 고정)
- **별님 카드**: 아바타, 이름, "기록 N건", "최근 {시각}"
  - "새 n": 그 별님을 대상으로 한 미확인 별님 기록 수 (반 공지는 반 탭에서 센다)
  - 상태 표시 (우선순위: 긴급 > 할 일)
    - 열린 긴급: 빨간 테두리 + "고온 {값}°"
    - 열린 할 일: 주황 테두리 + "할 일 {기한}"
  - **그리드 순서는 상태에 따라 바꾸지 않는다.** 선생님들이 별님 위치를 기억하기 때문이다 [확정]

### 3.3 별님 아카이브
- 프로필 카드: 아바타, 이름, 반 · 담임, "기록 N건 · {첫 기록 연월}부터 이어짐", **[별님카드 ›]**(별님카드 화면으로 이동)
- 필터: 모두 / 이 별님 기록 / 반 공지 (각각 건수 표시)
- 타임라인
  - 날짜 헤더 순서: 오늘 → 과거
  - 반 공지는 반 색 점선 카드로 표시
  - 체온 기록은 판정 색 점, 관찰은 초록 점
  - 할 일이 붙은 기록에는 할 일 박스(열림 / 완료)
  - **담임 변경 구분선**: "2026년 3월 · 담임 A → B 선생님. 이전 기록도 그대로 이어져요."
- **여기까지 읽음 선**
  - 오늘 묶음에서 마지막 미확인 기록 바로 아래에 넣는다.
  - 문구: "↑ 새 기록 n건 · 아래는 읽은 기록" + [새 기록 확인]
  - [새 기록 확인]은 이 별님의 미확인 기록과 그 반의 미확인 반 공지를 모두 확인 처리한다. 최신 기록에도 반영된다 (P3).
  - 미확인 기록 카드에는 "새 기록" 표시를 붙이고 테두리를 강조한다.

### 3.4 관찰 기록 작성 시트
| 영역 | 내용 |
|---|---|
| 반 탭 | 기본값: 아카이브에서 열면 그 별님의 반, 아니면 별님별 기록에서 선택된 반 |
| 대상 | "반 공지(우리 반 전체)" 또는 별님 하나 (단일 선택). 아카이브에서 열면 그 별님이 미리 선택됨 |
| 메모 | 필수. 라벨은 대상에 따라 "메모" / "{반} 반 공지" / "{이름} 별님에 대한 메모" |
| 빠른 문구 | 식사(다 드심 / 절반 / 거의 안 드심), 컨디션(기분 좋음 / 피곤해 보임 / 일찍 쉼), 체온(재측정 필요 / 물 자주 드림). 누르면 완성된 문장이 메모 끝에 새 줄로 붙는다. 정해진 입력 양식이 아니라 문장 입력 도우미다 |
| 말로 입력 | STT 결과를 메모 끝에 붙인다. 프로토타입은 시뮬레이션이다 [TBD: STT 엔진, 온디바이스 여부] |
| 사진 | 선택. 1장 [가정: 최대 장수] |
| 할 일로 넘기기 | 체크하면 기한 선택이 나온다: 점심 전 / 13:00 목욕 전 / 저녁 전 / 다음 근무조. 기본값은 "13:00 목욕 전" [가정] |
| 저장 위치 안내 | 대상에 따라 "인수인계 + 별님 아카이브" 또는 "반 공지 + {반} {n}명 아카이브" |
| 검증 | 대상 미선택: "먼저 어떤 별님의 기록인지 골라주세요." / 메모 비어 있음: "메모를 한 줄이라도 적어주세요." |

- 할 일 제목은 프로토타입에서 `{대상} · {메모 첫 줄 14자}…`로 자동 생성한다. 앱에서는 [TBD] 직접 입력란을 둘지 정해야 한다.
- 세부 동작
  - 반 탭을 바꾸면 선택한 대상과 오류 문구가 초기화된다.
  - 대상을 고르기 전에는 [기록 남기기] 버튼이 비활성(회색)이다.
  - 메모 입력란 안내 문구: "오늘 본 작은 변화나 다음 선생님이 알아야 할 일을 적어주세요."
  - 말로 입력 중에는 버튼이 빨간색 "듣는 중…"으로 바뀌고 깜빡인다. 끝나면 원래 상태로 돌아온다.
  - 사진을 넣으면 버튼이 "사진 1장 · 빼기"로 바뀌고 옆에 썸네일이 나온다.
  - 할 일 안내 문구: "인수인계에 [완료하기] 버튼이 붙고, 끝날 때까지 교대 요약에 남아요."
  - [X]로 닫으면 작성 내용은 버린다 [TBD: 임시저장 여부, 8장 오프라인과 연결]

### 3.5 체온 입력 시트 (재측정 · 할 일 완료)
- 맥락 표시
  - 긴급: "처음 측정 {값}° ({시각}). 38.0° 아래로 내려오면 긴급에서 내려가요."
  - 체온 할 일: "처음 측정 {값} ({시각}, {측정자})"
  - 부탁형 할 일: "부탁한 사람: {작성자} · {시각}"
- 숫자패드로 세 자리를 입력하면 소수점 한 자리 값이 된다 (예: 3·6·9 → 36.9°). [지움] / [⌫] 지원. 입력하는 동안 판정 색이 미리 보인다.
- 저장 가능 범위: 34.0~42.0° (체온 탭과 같음)
- 체온 측정이 아닌 할 일(kind=memo)은 [TBD] 숫자패드 없이 바로 완료 확인 시트를 띄워야 한다. 프로토타입은 모든 할 일에 숫자패드를 쓴다.
- 시트 제목: 긴급이면 "{이름} 별님 재측정", 할 일이면 할 일 제목
- 입력 전 안내: "숫자 세 자리를 눌러주세요 · 예) 3 6 9"
- 저장 버튼: "저장하고 완료" (범위 밖이거나 세 자리가 아니면 비활성)

### 3.6 화면 이동과 스크롤
| 상황 | 동작 |
|---|---|
| 같은 화면 안에서 상태만 바뀜 (확인, 답글 펼치기 등) | 스크롤 위치 유지 |
| 필터 변경 | 맨 위로 |
| 탭 전환, 별님 아카이브 진입, 뒤로 가기 | 맨 위로 |
| 요약 카드의 "긴급" | 첫 긴급 카드 위치로 |
| 아카이브의 "‹ {반} 별님 목록" | 별님별 기록으로 돌아가고 그 별님의 반 탭이 선택됨 |
| 카드의 [답글 n] | 카드 아래에 답글 목록과 입력란을 펼치고 닫음 (토글) |

## 4. 비즈니스 규칙

### 4.1 체온 판정
| 판정 | 범위 | 색 (ink / soft / line) |
|---|---|---|
| 고온 | ≥ 38.0 | #a8403f / #fbeaea / #dc8584 |
| 미열 | 37.0 ~ 37.9 | #8a5d12 / #fbf1dd / #d9a44e |
| 정상 | 36.0 ~ 36.9 | #4c7d62 / #e9f3ed / #75aa8d |
| 저온 | < 36.0 | #3f6ea0 / #e8f0fa / #6a9ed5 |

> ⚠️ **충돌**: 원본 체온 탭 흐름에는 "D. 39.0↑ 고온" 단계가 있는데, 판정 코드는 38.0부터 고온이다. 긴급을 만드는 기준값을 [TBD] 하나로 통일해야 한다. 간호 담당 확인이 필요하다.

### 4.2 긴급 생명주기
```
체온 저장 (체온 탭 또는 재측정)
  └ 판정이 고온 또는 저온 → Alert(open) 생성
       ├ 즉시: 간호 담당에게 푸시 알림 (notifiedAt 기록)
       ├ nextRemeasureAt = 측정 시각 + 30분 [가정]
       └ 재측정 입력
            ├ 아직 범위 밖 → attempts에 추가, nextRemeasureAt += 30분, 긴급 유지
            └ 범위 안 → Alert(resolved)
                 · 최신 기록에 "체온 기록 · 긴급 해제" 카드로 이동
                   (처음 값 → 재측정 값, 측정자)
                 · 재측정한 선생님은 자동 확인 처리
```
- 프로토타입은 고온만 시연한다. 저온 해제 기준은 [TBD] 36.0° 이상으로 돌아오면 해제할지 정해야 한다.
- 예정 시각이 지났는데 재측정이 없을 때의 알림은 [TBD] (5장 참고).
- 간호 담당이 "확인/조치" 단계를 따로 누를지 [TBD]. 지금은 자동 알림 1단계만 있다.

### 4.3 확인(Read)
- 미확인 = `작성자 ≠ 나` AND `내 ReadReceipt 없음`
- 미확인을 **세는 범위**는 3.1과 같다 (내 직전 근무 시작 이후 + 열린 할 일이 붙은 기록). 범위 밖의 미확인 기록은 요약, 세그먼트 배지, 반 탭 배지에서 세지 않는다. 별님 아카이브에서는 "새 기록"으로 표시한다.
- 열린 긴급은 미확인 집계에서 빼고 따로 센다.
- 확인 처리 경로와 `source`
  - `feed`: 카드의 [확인]
  - `archive`: 아카이브의 [새 기록 확인]
  - `reply`: 답글 작성 시 자동
  - `complete`: 할 일 완료 시 자동
  - `remeasure`: 긴급 해제 재측정 시 자동
- [확인]은 토글이라 사용자가 취소할 수 있다. 다만 서버에 확인 기록이 남아 있는 경우의 취소 허용 여부는 [TBD]. 감사 기록을 고려하면 취소도 이력으로 남기는 것을 권장한다.
- 분모 "/4"는 **현재 근무조 인원**이다 [가정]. 반 공지의 분모를 그 반 담당자로 줄일지 [TBD].

### 4.4 할 일(Task)
- 생성 경로
  1. 체온 기록이 미열이면 재측정 할 일 자동 생성 [가정: 자동 생성 조건. 프로토타입은 시드 데이터]
  2. 작성 시트의 "할 일로 넘기기"
  3. (프로토타입 시드) 관찰 메모의 부탁 → 할 일. 앱에서 자동 추출하지 않는다. 2번 경로로 만든다
- 상태: `open` → `done` (완료자, 완료 시각, 결과 체온)
- 완료하면 그 기록은 완료자에게 자동 확인 처리된다.
- 기한이 지났을 때의 표시와 알림은 [TBD].
- 다음 근무조로 넘어갈 때 열린 할 일은 그대로 남는다. **완료될 때까지 최신 기록(모두 · 할 일 필터)에 계속 보이고 교대 요약에서도 계속 센다** [확정]. 요약 숫자와 목록은 항상 일치해야 한다.
- 범위 밖에서 넘어온 할 일은 "이전 근무에서 넘어온 할 일 n · 완료할 때까지 남아요" 섹션에 생성 시각과 함께 표시한다. 예: "어제 15:20"
- 범위 밖 할 일을 완료하면, 지금 보고 있는 화면에서는 완료 상태로 남긴다. 다음에 들어올 때부터는 범위 밖이므로 아카이브에서만 보인다 [가정]
- 별님 아카이브에서는 어제 기록을 "어제 · {날짜}" 묶음으로 나눠 보여준다

### 4.5 공지
- 전체 공지: 사무국만 작성 (사무국 웹) [가정]. 앱에서는 읽기와 확인만 한다.
- 고정 해제와 만료: [TBD] 기간 설정, 또는 근무조 전원 확인 후 접기. 프로토타입은 무기한 고정이고, 확인하면 본문만 접는다.
- 반 공지: 앱에서 작성 가능. 그 반 별님 전원의 아카이브에 점선 카드로 들어간다.

### 4.6 답글
- 텍스트만. Enter 또는 [보내기]로 전송한다.
- 답글을 쓴 선생님은 그 기록이 확인 처리된다.
- 수정·삭제 [TBD] (4.7 따름)

### 4.7 수정·삭제와 이력 (프로토타입 없음, 실서비스 필수)
- 돌봄 기록은 근거 자료가 될 수 있다. **수정은 허용하되 이전 내용을 이력으로 남긴다** [권장].
- 삭제는 소프트 삭제 + 사유를 권장한다. 권한은 작성자 본인과 관리자 [TBD].

## 6. 데이터 모델 (초안)

```ts
type Scope = 'facility' | 'class' | 'star';
type Band = 'high' | 'mild' | 'ok' | 'low';

interface Staff   { id: string; name: string; role: 'teacher' | 'nurse' | 'office' | 'admin'; avatar: Avatar; }
interface Class   { id: string; name: string; color: string; homeroomId: string; }
interface Star    { id: string; classId: string; name: string; fullName?: string; avatar: Avatar; joinedAt: string; }
interface Shift   { id: string; date: string; type: 'am' | 'pm' | 'night'; staffIds: string[]; } // type 구분은 [TBD]

interface Entry {
  id: string;
  scope: Scope;
  classId?: string;            // facility면 없음
  starId?: string;             // scope === 'star'일 때만
  authorId: string;
  shiftId: string;
  kindLabel: string;           // "관찰 메모", "체온 기록 · 재측정 후", "반 공지" 등 표시용
  title?: string;              // 전체 공지
  body?: string;
  photos: Photo[];
  temperature?: { value: number; band: Band; measuredAt: string; note?: string };
  task?: Task;
  alert?: Alert;
  createdAt: string;
  updatedAt?: string;
  deletedAt?: string;
  revisions?: EntryRevision[]; // 4.7
}

interface Task {
  id: string;
  label: string;
  kind: 'temp' | 'memo';
  due: { preset: '점심 전' | '13:00 목욕 전' | '저녁 전' | '다음 근무조' | 'custom'; at?: string };
  status: 'open' | 'done';
  doneBy?: string; doneAt?: string; resultTemp?: number;
}

interface Alert {
  status: 'open' | 'resolved';
  initialValue: number;
  notifiedAt: string;
  nextRemeasureAt: string;
  attempts: { value: number; at: string; by: string }[];
  resolvedAt?: string; resolvedValue?: number; resolvedBy?: string;
}

interface ReadReceipt { entryId: string; staffId: string; readAt: string;
  source: 'feed' | 'archive' | 'reply' | 'complete' | 'remeasure'; revokedAt?: string; }

interface Reply { id: string; entryId: string; authorId: string; body: string; createdAt: string; }
```

- 별님 아카이브 조회 = `Entry where (scope='star' AND starId=X) OR (scope='class' AND classId=X.classId AND createdAt >= X.joinedAt)` 를 최신순으로
- 담임 변경 구분선은 `ClassHomeroomHistory`(classId, staffId, from, to)에서 만든다.
- 최신 기록의 기준 시각(3.1) = 나를 포함한 `Shift` 중 현재 근무 직전 것의 시작 시각. 근무표(Shift.staffIds)가 실제 출근과 맞아야 한다. 근무표를 어디서 받을지는 [TBD] (사무국 웹 입력 / 출근 체크 / 외부 근무표 연동).

## 10. 프로토타입과 실제 구현의 차이

| 프로토타입 | 실제 구현 |
|---|---|
| 데이터는 시드 + 메모리 (새로고침하면 초기화) | 서버 저장 |

## 11. 결정이 필요한 것 (우선순위순)

1. **근무 형태와 근무표 출처**: 교대 구분(오전/오후/야간?), 근무조 인원, 근무표 데이터를 어디서 받을지. 확인 분모, 교대 요약, **최신 기록의 기준 시각(방식 C)**이 모두 여기에 달려 있다.
2. **긴급 기준값**: 고온 38.0 vs 39.0, 저온 해제 기준, 재측정 간격 30분.
3. **확인 대상자**: 반 공지와 별님 기록의 분모를 근무조 전원으로 할지, 그 반 담당자로 할지.
4. **기기**: 개인 폰 / 공용 태블릿. 로그인, 사진, 알림 설계가 달라진다.
5. **공지 만료 규칙**: 기간 / 전원 확인 / 수동 해제.
