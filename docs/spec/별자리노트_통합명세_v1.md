## 1. 제품 한 줄과 원칙

**별님이 아프다고 말하지 못해도, 평소와 다른 체온을 바로 알아채고, 정해진 사람에게 빠르게 넘기고, 누가 무엇을 했는지 남긴다.**

| # | 원칙 | 출처 |
|---|---|---|
| P1 | 판단 기준은 **별님마다 다른 평소 체온(기저치)** 이다. 고정 숫자는 안전장치로만 쓴다 | 01, [C1] |
| P2 | 생활관은 **입력만 빠르게**, 사무국은 **PC로 한눈에**, 간호사·원장은 **알림으로** | 01 |
| P3 | 혜진원의 **기존 대응 경로**(관찰 → 원내 조제 → 원장 처방 → 병원)를 바꾸지 않고 기록만 돕는다 | 이상 대응 |
| P4 | 앱은 **투약 용량을 계산하거나 추천하지 않는다.** 의료진이 미리 쓴 지침을 보여주기만 한다 | 이상 대응 |
| P5 | **읽음 · 완료 · 이상 알림 확인**은 서로 다른 행동이다. 섞지 않는다 | 인수인계, 아카이브, [C6] |
| P6 | 기록은 지우지 않는다. 잘못된 기록은 **무효/취소 표시 + 새 기록**으로 바로잡는다 | 이상 대응, [C7] |
| P7 | 같은 사실은 **한 곳에만 저장**하고 다른 화면은 읽어서 보여준다 (측정, 이상 건, 읽음) | 아카이브, [C2] |
| P8 | 색만으로 구분하지 않는다. 기호와 글자를 함께 쓴다 | 전원 |
| P9 | 개발 중에는 **가짜 데이터만** 쓴다. 실제 별님 이름·사진·건강 정보를 넣지 않는다 | 01 |

## 2. 사용자와 역할

| 역할 (코드) | 누구 | 주로 쓰는 기기 | 핵심 행동 |
|---|---|---|---|
| 담임 `care` + 담임 표시 | 반마다 1명. 그 반 기록의 책임자 | 폰·생활관 태블릿 | 체온 입력, 인수인계 읽기·쓰기, 할 일 완료, 반 공지 |
| 근무 선생님 `care` | 담임이 아닌 생활관 선생님. 근무 배치로 **담당 반**을 받음 | 폰·생활관 태블릿 | 담임과 같음 (반 공지 포함) |
| 당직 선생님 `night` | 야간 근무조 선생님 (근무 배정으로 정해짐. 별도 직군 아님) | 폰 | 야간 긴급·이상 대응 알림 받기, 확인·초기 대응 |
| 간호사 `nurse` | 간호 담당 | 폰 | 이상 알림, 담당·투약 기록, 투약 지침·기저치 관리 |
| 사무국 `office` | 행복지원팀 | PC 웹 | 현황판, 전체 공지, 일정·근무표 관리 |
| 원장 `director` | 원장님 | 폰 | 위험 알림, 처방·병원 지시 |
| 관리자 `admin` | 사무국 중 지정 | PC 웹 | 계정, 반 측정 권한 부여 |

- 권한 표: 이상 대응 행동은 이상 대응 명세 3장, 기록 수정·삭제는 [TBD] (인수인계 4.7).
- **반 권한** [확정]: 기본은 담당 반만 입력 가능. 관리자가 다른 반 권한을 줄 수 있다. 조회 권한도 같은 체계를 따른다. 서버가 매 요청마다 다시 검사한다.
- 권한 없는 버튼은 숨기지 않고 흐리게 보여주고, 누르면 이유를 알려준다 (이상 대응 9장).

## 4. 앱 구조와 화면 이동

### 4-1. 공통 틀 [확정]
```
┌──────────────────────────────┐
│ 상단: 화면 제목 ·········· 🔔(n) │  ← 🔔 = 긴급·이상 대응 알림 목록 (이상 대응 S2)
│ (이상 알림 배너가 위에서 내려옴)  │
│                              │
│          탭 내용              │
│                              │
├──────────────────────────────┤
│  인수인계  ·  (◉ 퀵 체온)  ·  일정  │  ← 하단 메뉴 3개. 가운데는 원형 퀵 버튼
└──────────────────────────────┘
```
- 하단 메뉴는 **3개뿐**이다. 아카이브·이상 건·별님카드는 탭이 아니라 다른 화면에서 들어가는 상세 화면이다.
- 퀵 체온은 탭 위에 덮이는 **전체 화면 레이어**다. 가운데 버튼으로 펼치고 접는다.

**QT를 별님 지정으로 여는 방법** [확정 C4] — 퀵 체온 명세 2장 "가운데 버튼으로만 진입"을 아래처럼 넓힌다. 퀵 체온 담당이 원본 명세에 반영한다.
```
openQuickTemp({ residentId, reason: 'remeasure' | 'task' | 'schedule', caseId?, taskId? })
```
- 그 별님의 반·별님이 선택된 채로 펼친다. 초기값은 그 별님의 **마지막 측정값**(없으면 36.5).
- 위쪽에 맥락 한 줄을 보여준다: "재측정 · 처음 38.4℃ (10:11)" / "할 일 · 13:00 목욕 전 재측정".
- 저장 후 동작은 일반 저장과 같다. 연결된 할 일·이상 건 처리는 7장 흐름이 맡는다.
- 접으면 원래 화면으로 돌아간다.

## 5. 공통 규칙

### 5-1. 체온 값 [확정]
- 내부 저장은 **정수 ×10** (365 = 36.5℃) [C11]. 화면 표시는 소수 한 자리.
- 입력 범위 **34.0~42.0℃** [D7]. 범위 밖은 저장 불가. 의료적 정상 범위가 아니라 입력 제한이다.
- 단위 표기: ℃ (작은 글씨).

### 5-2. 판정 단계 [C1] [초안: 숫자는 간호사 확인]
기저치 대비 차이와 절대 기준 중 **더 심한 쪽**을 판정으로 쓴다 (01 4-3).

| 단계 (코드) | 기저치 대비 | 또는 절대 기준 | 앱이 하는 일 | 기호 |
|---|---|---|---|---|
| 평소 `normal` | +0.5 미만 | — | 저장만 | ✓ |
| 주의 `caution` | +0.5 이상 | 37.5 이상 | 재측정 안내 + **인수인계에 재측정 할 일 자동 생성 (30분)** [C10] | ! |
| 이상 `abnormal` | +1.0 이상 | 38.0 이상 | **이상 대응** 생성 + 푸시 | ▲ |
| 위험 `danger` | +1.5 이상 | 39.0 이상 | **긴급** 생성 (이상 대응 중이면 긴급으로 바뀜) + 중요 푸시 (원장 포함) | ⚠ |
| 저온 `low` | −1.0 이하 | 35.5 이하 | **이상 대응** 생성 + 푸시 | ▼ |

- 판단 순서: 위험 → 이상 → 저온 → 주의 → 평소.
- **판정은 저장 시점에 한 번 계산해 측정에 함께 저장한다** (당시 기저치·차이 포함). 나중에 기저치가 바뀌어도 과거 판정은 그대로 보인다. 아카이브·일정·인수인계는 저장된 판정을 읽기만 한다.
- 판정 계산 코드는 **한 곳**(`core/judgment`)에만 둔다. 화면마다 따로 만들지 않는다.

### 5-3. 기저치 (01 4-2) [초안]
- 최근 14일 측정 중 이상·위험·저온이 아니었던 값(평소·주의)의 **중앙값**. 무효 처리된 측정은 뺀다.

## 6. 기능별 정리 (통합하며 바뀐 점)

### 6-1. 퀵 체온 (QT)
원본 그대로: 반 탭 + 별님 프로필 줄 + 큰 이름 + 디지털 체온 + 원형 다이얼(6°당 0.1℃) + ± 버튼 + 0.5초 눌러 기록 + 제스처 안내, 반 측정 권한 잠금, 접기·펼치기 시 초안 유지.

**통합으로 바뀐 점**
1. 다른 화면에서 별님을 지정해 열 수 있다 (4-3). [C4]
2. 저장 성공 → 초록 "기록 완료"가 먼저 보이고, 판정이 이상·위험·저온이면 **약 0.6초 뒤 S1 시트**가 올라온다 (이상 대응 1-1). 주의면 토스트 "평소보다 조금 높아요 (+0.6). 30분 뒤 다시 재 주세요"와 함께 할 일이 생긴다 [C10].
3. 같은 별님을 다시 저장하면 **항상 새 측정**이다. 이미 저장한 값을 고치는 기능은 없다. 잘못 잰 경우는 S1 또는 아카이브 상세의 [잘못 쟀어요] → 무효 처리 후 다시 잰다 [C7].
4. 체온 입력은 앱 전체에서 이 화면 하나뿐이다. 인수인계의 숫자패드 시트는 만들지 않는다 [C4].
5. "아동" → "거주인/별님" [C12].

### 6-2. 이상 대응 (S1~S9)
원본 그대로: 이상 건 생성 → 알림 → [확인했어요] → [제가 맡을게요] → 대응 단계 ①~④ → [대응 종료]. 버튼 한 번 = 기록(CaseEvent) 한 줄, 지우지 않고 취소 표시. 투약 지침은 보여주기만.

**통합으로 바뀐 점**
1. **위험만 긴급** [C2 확정, 11/12 v1.2]. 데이터는 `Case` 하나뿐이고 인수인계에 별도 긴급 데이터를 만들지 않는다. 화면 이름만 둘로 나눈다.
   - 위험이 한 번이라도 나온 이상 건 → **"긴급"** (빨강 ⚠). 예: "긴급 · 위험 39.1℃", 🔔 "새 긴급".
   - 이상·저온만 나온 이상 건 → **"이상 대응"** (이상 주황 ▲, 저온 파랑 ▼). 예: "이상 대응 · 이상 38.4℃".
   - 이상 대응 중 위험이 나오면 같은 이상 건이 긴급으로 바뀐다 (새 이상 건 아님). 체온이 내려가도 종료될 때까지 긴급으로 남는다.
   - 코드: `Case.severity` = 지금까지 나온 판정 중 가장 심한 것. `isUrgent = severity == danger`.
2. **푸시 알림** [C9 확정]: 이상 대응이 생기면 근무 중인 생활관 선생님 전원과 담당자들에게 푸시를 보낸다. 긴급(위험)은 원장까지, 방해 금지를 무시하는 중요 알림으로 보낸다 (9장).
3. **회복 표시** [C3]: 재측정 판정이 평소·주의로 내려오면 이상 건에 `recoveredAt`을 기록하고 화면에 **"종료 대기"** 로 보인다. 인수인계 대응 칸에서는 내려가고, 🔔·S3·현황판에서는 종료될 때까지 보인다. S6의 기존 버튼 [한 번 더 재고 종료하기] / [지금 종료하기]는 그대로다. 다시 이상 이상으로 오르면 `recoveredAt`을 지우고 대응 칸에 다시 올라온다.
4. 주간/야간 구분을 근무표의 근무조로 바꾼다. "야간" = 야간 근무조 시간 [C8]. 당직 = 그 시간 야간 근무조에 배정된 선생님.
5. 이상 건이 생기면 인수인계에 **자동 기록(Entry)** 이 하나 생긴다: 종류 "체온 기록 · 이상 대응" (위험이면 "체온 기록 · 긴급"), 측정 ID와 이상 건 ID를 가리킴. 종료되면 같은 기록에 "종료 · 사유"가 붙는다 (새 기록 아님).
6. 별님카드의 대응 이력(S9)과 아카이브의 체온 행은 같은 이상 건 데이터를 읽는다.

### 6-3. 인수인계 (HO-1, HO-2, HO-W)
원본 그대로: 교대 요약 카드, 필터 칩, "내 직전 근무 시작 이후" 범위(방식 C), 고정 전체 공지, 열린 할 일은 완료까지 유지, 반 공지 → 반 전원 아카이브, 답글, 빠른 문구, 말로 입력, 사진 1장, 할 일로 넘기기, 별님 그리드 순서 고정.

**통합으로 바뀐 점**
1. **대응 칸 = 종료되지 않은 이상 건(Case) 중 `recoveredAt`이 없는 것** [C2][C3]. 칸 제목은 "긴급 · 이상 대응". **긴급이 맨 위**(빨강 테두리), 그다음 이상 대응을 최근 순으로. 카드 내용:
   - 라벨 "⚠ 긴급 · 위험 {최근 값}℃ · 평소보다 +{차이}" 또는 "▲ 이상 대응 · {판정} {최근 값}℃ · 평소보다 +{차이}"
   - 진행 줄: 대응 단계 ①~④ 중 현재 단계, "박소연 간호사 확인 · 담당" 또는 "아직 아무도 확인 안 함"
   - 다음 재측정 예정 시각
   - 버튼: [확인했어요] (이상 건 확인 [C6]) · [재측정 입력] (→ QT) · 카드 누르면 S3
2. 판정 이름을 고온/미열/정상/저온 → **평소/주의/이상/위험/저온**으로 바꾼다 [C1]. "미열이면 할 일 자동 생성"은 "주의이면"으로 바뀐다 [C10].
3. 체온 박스의 값은 측정(Measurement)에서 읽는다. Entry에 체온 숫자를 따로 저장하지 않는다 [D3].
4. 체온 할 일 [완료하기] → QT로 이동. QT에서 그 별님을 저장하면 할 일이 자동 완료(완료자 = 측정자, 결과 체온 = 측정 ID) [C4]. 메모 할 일은 확인 시트만.
5. 교대 요약의 "체온 미기록"은 일정의 측정 시점(`tempSlot`)이 지났는데 측정이 없는 별님 수다 (7-3).
6. 3.5장 숫자패드 시트는 삭제.

### 6-4. 별님 아카이브 (AR) [D1]
- 한 화면이다. **목록·기록 찾기·기록 상세 UI는 아카이브 명세**, **[새 기록 확인]·작성·할 일 규칙은 인수인계 명세**를 따른다.
- 열기만 해서는 읽음 처리하지 않는다. [새 기록 확인]은 필터·검색이 없는 "모두"에서만 보인다 (아카이브 4장).
- 체온 행은 **측정 한 건 = 한 줄**. 그 측정으로 생긴 인수인계 기록·할 일·이상 건은 행 안에서 링크로만 연결한다 (아카이브 5장 M17/H9 규칙).
- 무효 처리된 측정은 취소선 + "잘못 잰 값"으로 보인다 [C7].
- 담임 변경 구분선은 담임 이력(`ClassHomeroomHistory`)에서 만든다.

### 6-5. 일정 (SC-1, SC-2, SC-U)
원본 그대로. 일정은 판정하지 않고 **측정의 저장된 판정**과 **이상 건 진행 여부**를 읽어서 보여준다.

**통합으로 바뀐 점**
1. 카드의 판정 기호·색은 5-2·5-4를 따른다 (일정 명세가 이미 같은 5단계 이름을 씀).
2. 카드 표시 이름: 그 별님에게 **종료되지 않은 이상 건**이 있으면 (종료 대기 포함) "이상 대응 중", 그 이상 건이 긴급이면 **"긴급"** (빨강). 누르면 S3.
3. 일정의 `tempSlot`(am / pm_bath / pm_return)이 앱 전체의 **측정 시점 기준**이다. 인수인계의 "체온 미기록"과 일정 카드의 "미기록"이 같은 계산을 쓴다 (7-3).
4. 파일 올리기 해석 범위는 [TBD] (일정 13장 2번). 금요일은 시제품처럼 고정 예시.

### 6-6. 별님카드 (PF) — 명세 없음, 최소안 [제안]
여러 기능이 가리키지만 담당이 없다 (빈 곳 G1). 금요일 시연용 최소 구성:

- 평소 체온(기저치) + "최근 14일 중앙값" 설명 + 최근 14일 체온 작은 그래프
- [투약 지침 보기] → S4 (지침 작성·수정은 간호사·원장만, 금요일엔 시드 데이터)
- 대응 이력 (S9)
- [이 별님의 기록 아카이브] → AR

### 6-7. 사무국 PC 웹 (DESK) [v1.3 추가]
원본: `별자리노트_사무국PC_웹_기능.md`. 메뉴·표 구성·권한·오류 처리는 원본을 따른다. 사무국 웹은 **조회용**이다. 화면을 열거나 닫아도 확인·담당·종료 상태가 바뀌지 않는다 (원본 4장).

| 메뉴 (원본) | 화면 ID | 금요일 |
|---|---|---|
| 오늘 현황 (첫 화면) | DESK-1 | 필수 |
| 별님 기록 | DESK-2 | 필수 |
| 이상 대응 현황 → 이름을 **긴급·이상 대응 현황**으로 | DESK-3 (= 이상 대응 S8) | 필수 |
| 반별 일정 / 전체 시간표 | DESK-4 | 후속 |
| 일정 파일 가져오기 / 기록 내보내기 | DESK-5 | 후속 (내보내기 = 빈 곳 G6) |

**통합으로 바뀐 점**
1. **정정** [C7]: 원본 3장의 "정정은 기존 측정에 반영"을 바꾼다. 측정은 고치지 않고 무효 처리 + 새 측정(`correctsId`)이다. 웹 타임라인·추이 그래프는 무효 측정을 빼고 그리며, 타임라인에는 취소선 + "잘못 잰 값"으로 남긴다 (앱 아카이브와 같음).
2. **판정·기저치**: 웹은 판정을 새로 계산하지 않고 측정에 저장된 판정을 그대로 보여준다 (원본과 5-2 모두 같음). 원본의 "기준 미등록"은 통합 규칙에 맞춰 **"기저치 계산 중 (기록 n/10)"** 으로 쓴다 (5-3: 기록 10개 미만이면 36.5로 계산하되 이렇게 표시).
3. **긴급·이상 대응** [C2 v1.2]: 진행 중 표에서 **긴급(위험)이 맨 위**, 빨강 + "긴급" 글자. 이상·저온은 "이상 대응". `recoveredAt`이 있으면 "종료 대기"로 진행 중 탭에 남는다 [C3].
4. **"먼저 살펴볼 별님"** (원본 2장) = 열린 이상 건(긴급 → 이상 대응 순) + 오늘 **주의** 측정 중 재측정 할 일이 아직 열린 것. 같은 측정에 연결된 것은 한 줄.
5. **"기록 있음/없음"** (원본 2장): 오늘 측정이 하나라도 있는 별님 수로 센다. 앱의 **"체온 미기록"**(측정 시점이 지났는데 기록 없음, 7-3)과는 다른 숫자이므로 웹에서는 원본 이름 그대로 "오늘 체온 기록 없음"을 쓰고 "미기록"이라 부르지 않는다.
6. **타임라인**은 앱 아카이브와 같은 데이터·규칙이다 (측정 한 건 = 한 줄, 반 공지는 원본 한 건 참조, 담임 변경선). 웹 코드도 같은 Repository를 쓴다.
7. **갱신**: 새 측정·이상 건 변화가 오면 표와 숫자만 바꾸고, 보고 있는 상세는 닫지 않는다. 금요일 시연은 같은 기기의 가짜 저장소를 공유하므로 바로 반영된다.
8. **권한·로그아웃** (원본 6장)은 로그인(빈 곳 G4)이 생기면 적용한다. 금요일은 역할 바꾸기 버튼의 "사무국"으로 들어간다.

### 7-1. 체온 한 번 저장할 때
```
QT 0.5초 누름
  └ 측정 저장 요청 (residentId, value, measuredAt, recordedBy)
       ├ 실패 → 입력 유지, 재시도 (아무것도 안 생김)
       └ 성공 → Measurement 생성 + 판정 계산해서 함께 저장 (stage, baseline, diff)
            ├ QT: 초록 "기록 완료"
            ├ 그 별님에게 열린 체온 할 일이 있으면 → Task 완료 (doneBy, resultMeasurementId)
            ├ 그 별님에게 진행 중인 이상 건이 있으면 → 재측정으로 붙임 (CaseEvent: remeasured)
            │     └ 판정이 평소·주의로 내려옴 → recoveredAt 기록 (종료 대기)
            │     └ 위험으로 오름 → 원장 자동 알림 (이상 대응 A-06)
            ├ (진행 중인 이상 건 없음) 판정 = 이상·위험·저온
            │     → Case 생성 + 알림 발송 + 인수인계 Entry(체온 기록·이상) 생성 + S1 표시
            ├ (진행 중인 이상 건 없음) 판정 = 주의
            │     → 인수인계 Entry(체온 기록·주의) + Task(재측정, 기한 30분) 자동 생성
            └ 판정 = 평소 → 측정만 (인수인계에 따로 올리지 않음. 아카이브·일정 카드에는 보임)
```

## 8. 공통 데이터 모델 (초안)

> 이름 규칙: 별님은 `residentId`, 체온은 정수 ×10, 시각은 ISO 문자열 (서버 시각) [C11]. Flutter에서는 같은 이름으로 Dart 클래스를 만든다.

```ts
// ── 사람·조직
Staff        { id, name, role: 'care'|'nurse'|'office'|'director'|'admin', phone?, avatar }
Class        { id, name /*양자리반*/, color, homeroomId, order }
Resident     { id /*가명 코드 R-A02*/, classId, name, avatar, joinedAt, baselineManual?: int }
ClassHomeroomHistory { classId, staffId, from, to? }
ClassPermission      { staffId, classId, canMeasure, canView, grantedBy, grantedAt }
Shift        { id, date, type: 'am'|'pm'|'night', startAt, endAt, staffIds[] }   // 시간은 [확인 필요]
ShiftAssignment { shiftId, staffId, classId? /*근무 선생님의 배치 반. 담임은 Class.homeroomId*/, isNightDuty? }

// ── 체온 (원본)
Measurement {
  id, residentId, classId, value: int, measuredAt, recordedBy, savedAt,
  source: 'quick' | 'ble',
  slot?: 'am'|'pm_bath'|'pm_return',
  judgment: { stage: 'normal'|'caution'|'abnormal'|'danger'|'low', baseline: int, diff: int },
  caseId?,                       // 이 측정이 시작했거나 붙은 이상 건
  voidedAt?, voidedBy?, voidReason?,
  correctsId?                    // 무효 처리한 측정을 대신하는 새 측정이면 그 ID [C7]
}

// ── 이상 대응 (원본: 이상 대응 명세 8장)
Case {
  id, residentId, classId, severity: 'abnormal'|'danger'|'low',
  status: 'unacked'|'acked'|'active'|'waiting_remeasure'|'closed',
  stage: 1|2|3|4, assigneeId?, firstMeasurementId, firstTemp: int, baseline: int,
  remeasureAt?, recoveredAt? /*[C3] 종료 대기*/, createdAt, closedAt?, closeReason?
}
CaseEvent { id, caseId, type /*이상 대응 8장 목록*/, actorId /*system 가능*/, actorRole, at, data, voidedBy? }
MedicationGuideline { residentId, body, writtenBy, updatedAt, approvedBy? }

// ── 인수인계 (원본: 인수인계 6장)
Entry {
  id, scope: 'facility'|'class'|'resident', classId?, residentId?,
  authorId /*자동 생성이면 system*/, shiftId, kindLabel, title?, body?, photos[],
  measurementId?, caseId?,       // [D3] 체온 숫자는 여기 저장하지 않음
  task?: Task, createdAt, updatedAt?, deletedAt?, revisions?[]
}
Task { id, label, kind: 'temp'|'memo', due: { preset, at? }, status: 'open'|'done',
       auto: boolean /*주의 판정으로 자동 생성*/, doneBy?, doneAt?, resultMeasurementId? }
ReadReceipt { entryId, staffId, readAt, source: 'feed'|'archive'|'reply'|'complete'|'remeasure', revokedAt? }
Reply { id, entryId, authorId, body, createdAt }

// ── 일정 (원본: 일정 9장)
ScheduleItem { id, scope, classId?, residentId?, date, startAt, endAt, title, place,
               kind, staffId?, staffName?, tempSlot?, sourceFileId?, updatedAt }
ScheduleUpload { id, fileName, status, rows[], uploadedBy, uploadedAt }
```

- 인수인계 Entry의 `scope` 값 `'star'` → `'resident'`로 바꾼다 [C11].

## 9. 알림 규칙 (통합) [C9 확정: 푸시]

이상 대응과 긴급은 **푸시 알림**으로 사람들에게 바로 간다. 앱이 꺼져 있어도 폰 알림으로 뜨고, 앱 안에서는 위쪽 배너와 🔔로도 보인다. **긴급(위험)은 받는 사람이 더 많고, 다시 알림이 더 빠르고, 방해 금지를 무시한다.**

| 일 | 푸시 받는 사람 | 다시 알림 |
|---|---|---|
| 이상 대응 생성 (이상·저온) | **지금 근무 중인 생활관 선생님 전원** + 간호사 + 사무국 (야간: 당직 + 간호사) | 15분 동안 아무도 [확인했어요]를 안 누르면 다음 사람 [초안] |
| **긴급** 생성 (위험) | 위 사람 전원 + **원장** · 중요 알림 | 5분 [초안] |
| 누군가 [확인했어요] / [제가 맡을게요] | 처음 알림 받은 사람 전원 ("박소연 간호사가 맡았어요") | — |
| 재측정 예정 시각 | 담당자 + 그 반 근무 선생님 | 10분 지나도 재측정 없으면 한 번 더 |
| 이상 대응 → **긴급**으로 바뀜 (위험으로 오름) | 원장 + 처음 알림 받은 사람 전원 · 중요 알림 | 5분 [초안] |
| 대응 단계 변경 | 이상 대응 S5 표의 사람 | — |
| 이상 대응·긴급 종료 | 처음 알림 받은 사람 전원 | — |
| 근무조가 바뀔 때 진행 중 이상 건 있음 | 새 근무조 전원 ("넘겨받은 긴급 N개 · 이상 대응 N개") | — |
| 전체 공지 · 반 공지 · 내 기록에 답글 · 할 일 기한 | [TBD] 인수인계 5장 제안대로 | — |

- 같은 이상 건에 대한 알림은 한 사람에게 **1분에 한 번까지만** 묶어서 보낸다 (알림 폭탄 방지).
- 다음 사람 순서는 이상 대응 7장 표를 따른다.
- 푸시를 보내려면 서버가 필요하다 (Firebase Cloud Messaging 등, G5·G7). **금요일 시연은 앱 안 배너 + 기기 로컬 알림**으로 대신한다.
- 방해 금지: **긴급** 푸시는 언제나 방해 금지를 무시하는 "중요 알림"으로 보낸다. 이상 대응 푸시는 야간 당직에게만 중요 알림, 나머지는 일반 알림이다 [제안]. 공지 푸시는 야간에 보내지 않는다 [제안].

### 11-3. 금요일 시연에서 기기별 주의
- **Android**: `flutter build apk`로 설치 파일을 만들어 폰에 바로 설치할 수 있다.
- **iOS**: 아이폰에 설치하려면 **Mac + Xcode**가 필요하다 (무료 Apple 계정으로 7일짜리 설치 가능). 팀에 Mac이 없으면 **Flutter Web으로 빌드해 아이폰 Safari에서 여는 것**이 대안이다 (같은 코드, 푸시 알림만 안 됨).
- 기기 간 실시간 공유는 서버가 있어야 하므로, 금요일은 **한 기기 안에서 역할 바꾸기**로 흐름을 보여준다 (이상 대응 시연 방식).
