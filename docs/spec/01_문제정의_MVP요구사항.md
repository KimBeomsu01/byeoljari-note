## 0. 한눈에 보기

- **무엇을 만드나:** 생활관에서 잰 체온을 **그 별님의 평소 체온과 비교해** "이상 있음/없음"을 바로 보여주고, 이상이면 **간호사·사무국·원장님께 바로 전달**되는 웹앱
- **무엇을 안 만드나:** 새로운 의료 기능(투약 용량 계산, 화상 진료 등). 혜진원에 **이미 있는 대응 경로**로 빨리 전달하는 데까지만 해요.
- **처음 목표:** 실제 데이터 없이 가짜 데이터로 MVP를 완성하고, 현장 확인 후 시범운영

## 1. 문제 정의

### 1-1. 문제 한 문장

> **생활관에서 잰 체온이 그 별님의 평소 체온에 비해 이상한지 바로 판단하기 어렵고, 이상이 생겨도 간호사·사무국·원장님께 빠르게 전달되지 않아 대응이 늦어진다.**

### 1-2. 중간발표 이후 무엇이 바뀌었나

| | 중간발표(10/28)까지의 생각 | 피드백 후 바뀐 생각 |
|---|---|---|
| 핵심 문제 | 체온을 정기적으로 재고 기록하는 일이 부담 | 측정은 이미 하고 있음. **재고 난 뒤의 판단과 전달**이 문제 |
| 판단 기준 | 모든 별님에게 같은 기준(37℃, 39℃) | **별님마다 다른 평소 체온(기저치)** 기준 |
| 기저치 기능 | 2단계(나중)로 미뤄둠 | **1순위**로 올림 |
| 앱 사용 방식 | 담임 선생님 폰 하나로 다 함 | **공간별로 역할을 나눔** (생활관=입력, 사무국=확인) |
| 기존 문서 | 엑셀·한글 → 앱으로 가져오기 | **앱 → 엑셀로 내보내기**도 필요 |

## 3. MVP 필수 기능

> MVP = 현장에서 실제로 써볼 수 있는 **가장 작은 버전**이에요. 아래 6개가 모두 되면 시범운영을 시작할 수 있어요.

### F1. 별님 프로필 (기저치 포함)
- 이름(시범운영 때는 가명 코드), 반, 담임
- **평소 체온(기저치)**: 자동 계산값 + 간호사가 직접 입력한 값 (4장 참고)
- 의료 이력 요약: 장애 특성, 수술·입원 이력, 복용 약 (서류에서 옮겨 적기)
- **투약 지침 메모**: 원장님·간호사가 미리 써둔 내용을 **그대로 보여주기만** 함 (예: "38.5℃ 이상이면 OO 시럽 5ml, 간호사에게 먼저 연락")
- 접근 권한: 의료 이력·투약 지침은 **간호사·원장·사무국만** 수정할 수 있음

### F2. 체온 입력 (생활관용)
- 별님 선택 → 숫자 3개(3·6·8 → 36.8℃) → 저장. 프로토타입 흐름을 그대로 사용
- 저장하면 바로 현황판에 반영
- 입력한 사람과 시각을 자동으로 기록
- 2차: 블루투스 체온계로 숫자 자동 입력 (수동 입력이 완성된 다음)

### F3. 기저치 대비 이탈 표시
- 입력하는 순간 **"평소보다 +0.9℃"**처럼 차이를 크게 보여줌
- 색깔로 단계 표시: 평소 / 주의 / 이상 / 위험 (기준은 4장)
- 단계별 안내 문구: "1~2분 쉬었다가 다시 재주세요", "간호사에게 알려주세요" 등

### F4. 이상 알림 & 대응 기록 (기존 대응 경로 사용)
- '이상' 이상이면 사무국 현황판과 간호사에게 **자동 알림**
- 알림 카드에 기록하는 내용:
  1. 누가 확인했는지와 확인 시각 (프로토타입의 "확인" 버튼)
  2. 어느 단계로 대응했는지: **① 관찰·재측정 → ② 원내 조제 → ③ 원장 처방 → ④ 인근 병원**
  3. 조치 메모와 재측정 결과
- 확인한 사람이 없으면 일정 시간 뒤 다음 담당자에게 다시 알림 **[초안: 30분]**
- 야간 연락 순서는 혜진원 답변에 맞춰 설정 **[확인 필요]**

### F5. 사무국 현황판 (PC 웹)
- 반별로 오늘 측정 현황 표시: 측정 완료, 미측정, 주의·이상
- **위험한 별님이 맨 위**에 오게 정렬 (위험 → 이상 → 주의 → 미측정 → 평소)
- 별님을 누르면 별님 카드로 이동: 최근 체온 그래프, 기저치, 의료 이력, 대응 기록

### F6. 엑셀 내보내기
- 기간과 반을 골라 체온 기록과 대응 기록을 `.xlsx` 파일로 다운로드
- 별님 프로필 목록도 내보내기
- 이유: 혜진원이 익숙한 도구로 데이터를 계속 관리할 수 있게 하기 위해서예요. 앱 유지보수가 끊겨도 데이터가 남아요.

### 중간발표 기능 중 남기는 것 / 미루는 것

| 기능 | MVP에서 | 이유 |
|---|---|---|
| 관찰 메모·인수인계 | **간단히 남김** (별님 카드에 메모) | 체온과 함께 맥락을 공유해야 하므로 |
| 공지·안읽음 표시 | 미룸 | 카카오워크로도 가능함 |
| 반별 일정 | 미룸 | 핵심 문제(판단·전달)와 거리가 있음 |

## 4. 체온 판단 기준

### 4-1. 지금 기준이 서로 달라요 (먼저 정리해야 함)

| 구간 | 발표자료 (11쪽) | 프로토타입 (화면 범례·코드) |
|---|---|---|
| 정상 | ~36.9℃ | 36.0–36.9℃ |
| 미열 | 37.0–38.9℃ | 37.x℃ |
| 고온 | **39.0℃ 이상** | **38℃ 이상** |
| 고온 위험 | (없음) | 39℃ 이상 |
| 저온 | (없음) | 35.9℃ 이하 |
| 재측정 안내 | 37.0℃ 이상 → 30분 뒤 | 37도대 → 1~2분 쉬고 다시. 발열 → 30분 뒤 |

→ **38.0~38.9℃를 '미열'로 볼지 '고온'으로 볼지**가 서로 달라요. 이 구간은 해열제 판단과 직결되기 때문에 **간호사 선생님이 기준을 정해주셔야 해요.** 팀이 임의로 정하지 않아요.

### 4-2. 기저치(평소 체온) 계산 규칙 [초안]

> 아래 숫자는 팀의 출발점일 뿐이고 **간호사 선생님 검토 후 확정**해요.

1. **계산 방법:** 그 별님의 **최근 14일 기록 중 '이상'이 아니었던 값의 중간값**
   - 평균 대신 중간값을 쓰는 이유: 한두 번 잘못 잰 값에 덜 흔들려요.
   - 열이 났던 날은 계산에서 빼요. 그래야 기저치가 따라 올라가지 않아요.
2. **시간대 구분:** 오전과 오후 체온이 다를 수 있으니, 기록이 충분히 쌓이면 시간대별로 따로 계산해요.
3. **기록이 부족할 때 (10개 미만):**
   - 간호사가 입력한 평소 체온이 있으면 그 값을 써요.
   - 없으면 36.5℃를 임시로 쓰고, 화면에 "기저치 계산 중"이라고 표시해요.
4. **간호사 직접 지정이 우선:** 간호사가 값을 직접 넣으면 자동 계산보다 우선 적용해요.

### 4-3. 이탈 단계 [초안]

두 가지 규칙을 **함께** 써요. 둘 중 더 위험한 쪽으로 판정해요.

| 단계 | 기저치 대비 | 절대 기준 (안전장치) | 앱이 하는 일 |
|---|---|---|---|
| 평소 | +0.5℃ 미만 | — | 저장만 |
| 주의 | +0.5 ~ +0.9℃ | 37.5℃ 이상 **[확인 필요]** | 재측정 안내 |
| 이상 | +1.0℃ 이상 | 38.0℃ 이상 **[확인 필요]** | 사무국·간호사 알림 |
| 위험 | +1.5℃ 이상 | 39.0℃ 이상 | 즉시 알림 + 대응 기록 필수 |
| 저온 | −1.0℃ 이하 | 35.5℃ 이하 **[확인 필요]** | 재측정 안내 + 알림 |

- **절대 기준이 필요한 이유:** 평소 체온이 낮은 별님은 +1.0℃로는 놓칠 수 있고, 반대로 기저치 계산이 잘못될 수도 있어요. 그래서 절대 기준을 안전장치로 함께 둬요.
- **주의:** 앱은 "이상할 수 있다"는 **판단 보조**만 해요. 진단이나 투약 결정은 하지 않아요.

## 5. 이번엔 안 하는 것

| 하지 않는 것 | 이유 |
|---|---|
| **해열제 용량 자동 계산·추천** | 의료 판단이라 책임 문제가 있고 의료기기 규제에 걸릴 수 있어요. 대신 **미리 써둔 투약 지침을 보여주기만** 해요 (F1) |
| 화상 진료, 원격 처방 | 대응 체계가 이미 있어요 (피드백 1) |
| AI 시간표 자동 변환 (hwpx·엑셀) | 핵심 문제와 거리가 있어요 |
| 열화상 카메라·rPPG 자동 감지 | 비용·정확도·현장 정착 문제로 1차 피드백에서 보류 |
| 혈압·혈당 등 다른 수치 | 체온부터 제대로 정착시킨 다음에 해요 |
| 재난 대피 모드 | 범위 밖 (후속 과제) |
| 반별 일정·공지 고도화 | MVP 이후 |
| 블루투스 자동 입력 | 수동 입력 완성 후 **2차**로 (조사는 따로 진행 중) |

## 6. 개인정보 원칙 (개발할 때 지킬 것)

1. **개발 중에는 가짜 데이터만** 써요. 실제 이름이나 체온은 절대 넣지 않아요.
2. 시범운영 때는 **가명 코드**(예: 별님 A-03)를 쓰고, 실명 대조표는 혜진원 안에만 둬요.
3. 의료 이력·투약 지침은 **역할별 권한**으로 보호해요 (2장 표).
4. 서버 위치(국내 리전 또는 원내 PC)는 운영진·혜진원과 상의해서 정해요. 앱은 **서버를 바꾸기 쉽게** 만들어요.
5. 실제 데이터를 쓰기 전에 **시설 승인과 동의서**를 받아요.

## 7. 혜진원에 확인할 질문

### 기기·환경
1. 생활관 선생님들이 쓰는 폰·태블릿은 **안드로이드인가요, 아이폰인가요?** 기관 공용 기기가 있나요? *(블루투스 연동이 안드로이드에서만 쉬워요)*
2. **생활관에 와이파이가 되나요?** 신호가 약한 곳은 없나요?
3. 사무국 PC는 어떤 브라우저를 쓰나요? (크롬, 엣지 등)

### 대응 경로
4. **야간에 고온이 생기면 누구에게, 어떤 순서로 연락하나요?** (당직 → 간호사 → 원장님?) 연락은 전화인가요, 카카오톡인가요?
5. 원내 조제 → 원장 처방 → 병원으로 넘어가는 **기준**이 정해져 있나요?
6. 알림을 누가 받아야 하나요? 몇 분 안에 확인이 없으면 다음 사람에게 넘겨야 하나요?

### 기준·서류
7. **별님별 투약 지침 문서가 있나요?** (해열제 종류, 용량, 연락 기준)
8. 간호사 선생님께서 **체온 구간 기준**(4-1 표의 38℃대)을 정해주실 수 있나요?
9. **과거 체온 기록**이 있나요? 종이인가요, 엑셀인가요? 몇 달 치인가요? *(있으면 기저치를 바로 계산할 수 있어요)*
10. 별님들의 평소 체온을 간호사 선생님이 이미 알고 계신가요?
11. 체온계 종류는 무엇인가요? (귀, 이마, 겨드랑이) *(측정 부위마다 정상 범위가 달라요)*

### 운영
12. 간호사 근무 형태가 어떻게 되나요? (주 1회 방문인지, 수시 라운딩인지)
13. 하루에 몇 번, 언제 체온을 재나요?
14. 시범운영 때 앱을 쓸 선생님 계정은 몇 개 필요한가요? 실제 데이터를 쓰려면 어떤 동의 절차가 필요한가요?

## 8. 성공 지표

| 지표 | 측정 방법 | 목표 [초안] |
|---|---|---|
| **이상 전달 시간** | 이상 체온 입력 → 간호사·사무국이 처음 확인하기까지 걸린 시간 | 평균 10분 이내 |
| **대응 기록률** | '이상' 이상 건 중 대응 단계가 기록된 비율 | 90% 이상 |
| 체온 기록률 | 측정 예정 횟수 대비 실제 입력 | 전원 하루 2회의 90% |
| 입력 시간 | 별님 선택 → 저장까지 | 10초 이내 |
| 판단 도움 정도 | 선생님 설문: "이 수치가 이상인지 판단하기 쉬워졌다" (5점 척도) | 평균 4점 이상 |
| 이상 조기 발견 | 시범 기간 중 앱 알림으로 먼저 알게 된 사례 수 | 사례로 기록 |
| 내보내기 활용 | 사무국이 엑셀로 내보낸 횟수 | 시범 기간 중 1회 이상 |

> 비교 기준을 위해 **시범운영 전에** 현재 상황(전화로 전달하는 데 걸리는 시간 등)을 먼저 물어봐 두면 좋아요.

## 9. 팀이 결정해야 할 것

1. **체온 기준:** 간호사 선생님께 4-1·4-3 표를 보여드리고 기준 확정받기 (특히 38℃대)
2. **기저치 규칙:** 14일, 중간값, +0.5/+1.0/+1.5℃ 초안을 그대로 쓸지
3. **알림 방식:** 앱 안 알림만 할지, 카카오톡이나 문자 연동까지 할지 (야간 연락 답변에 따라)
4. **관찰 메모·인수인계를 MVP에 얼마나 남길지**
5. **서버:** 개발은 무료 서버와 가짜 데이터로 하고, 시범운영 서버는 운영진 답변을 받아서 결정
6. **질문 전달:** 7장 질문을 언제, 누가 혜진원에 전달할지
