# 별자리노트 · 모바일 앱 기능명세 (APP_기능명세.md)

- 담당: 어플(범수) · 작성일: 2026-11-26 · 대상 사용자: 생활관 선생님 (휴대폰)
- 짝 파일: `index.html`(조작 가능한 시안), `APP_통합메모.md`(연결·미확인 사항)
- 표시: **[원본 유지]** 기존 화면·규칙을 그대로 둠 · **[신규 제안]** 이번에 더한 것 · **[팀 확인 필요]** 팀이 정해야 함

> **이 문서의 범위.** UI 시안과 그 동작 규칙입니다. 실제 앱(Flutter) 코드 반영, 휴대폰 설치, 서버 동기화는 **하지 않았습니다.** 시안의 저장은 브라우저 화면 안에만 남고 새로고침하면 사라집니다. 이름·체온·일정은 모두 가상입니다.
>
> **만들지 않은 것.** 체온 판정 기준, 재측정 간격, 투약 규칙은 새로 정하지 않았습니다. 시안에 보이는 "주의·긴급"과 "10:15 예정"은 가상 시드에 미리 적어 둔 글자이고, 새로 입력한 체온에는 판정을 붙이지 않고 "공통 로직 결과 표시 자리"로 비워 두었습니다.

## 1. 작업 범위 (5줄)

1. 생활관 선생님의 한 흐름을 잇는다: 인수인계 → 별님 선택 → 퀵 체온 기록 → 저장 결과 → 같은 별님의 카드·아카이브.
2. 알림에서 관련 별님의 대응 기록으로 바로 간다.
3. 개선은 세 가지만: 저장 상태(저장 중·성공·실패), 별님별 기록 연결, 읽음 확인과 업무 완료의 구분.
4. 일정은 모바일 달력을 만들지 않고 별님카드 안 읽기 전용 요약만 제안한다 (일정 v2 §6-13).
5. PC 현황판·간호 선생님 호출함·의료진 포털은 고치지 않고 연결 대상으로만 적는다.

## 3. 화면별 명세

### 3-1. 인수인계

**답하는 질문:** 지금 내가 챙길 별님과 남은 일이 무엇인가?

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 보기 전환 | 최신 기록 / 별님별 | [원본 유지] |
| 요약 카드 | 미확인 n · 할 일 n · 체온 미기록 n (내 담당 반 기준) | [원본 유지], 미확인과 할 일을 따로 세는 것은 [신규 제안] |
| 필터 칩 | 모두 · 미확인 · 할 일 | [원본 유지] |
| 기록 카드 | 반 · 별님 이름 · 작성자·시각 · 체온(평소 대비 차이) · 내용 | [원본 유지] |
| 상태 두 칸 | **읽음 확인**(아직 안 읽음 / 내가 확인함) · **업무**(○○ 남음 / 완료 / 할 일 없음) | [신규 제안] |

| 버튼 | 동작 | 결과 | 실패·예외 |
|---|---|---|---|
| 별님 이름 | 그 별님의 별님카드로 이동 | 뒤로 가면 인수인계로 돌아옴 | — |
| 확인했어요 | 그 기록의 **읽음 확인만** 바꿈 | 미확인 수 −1. 업무 상태는 그대로 | 실제 앱: 저장 실패 시 버튼을 되돌리고 알림 [팀 확인 필요] |
| 재측정하기 (체온 할 일) | 그 별님을 대상으로 퀵 체온을 엶 | 저장에 성공하면 그 할 일이 완료됨 | 저장 실패 시 할 일은 남음 |
| 완료했어요 (메모 할 일) | 그 기록의 **업무만** 완료로 바꿈 | 할 일 수 −1. 읽음 확인은 그대로 | 위와 같음 |
| 상세 | 기록 상세 시트를 엶 | **열어 본 것만으로는 읽음·완료가 바뀌지 않음** | — |

빈 상태: "안 읽은 기록이 없어요" / "남은 할 일이 없어요" / "오늘 기록이 아직 없어요".
별님별 보기: 별님 한 줄에 미확인·할 일·체온 미기록 배지. 남은 것이 없으면 "남은 일 없음". 누르면 별님카드.

### 3-2. 퀵 체온

**답하는 질문:** 누구의 체온을 얼마로 기록하는가?

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 반 칩 · 별님 동그라미 | 반 명단에서 고름. 오늘 기록이 있는 별님은 초록 테두리 | [원본 유지] |
| **기록 대상 띠** | "은하수자리 · 이서준 / 평소 37.1°"를 값 위에 항상 보여 줌 | [신규 제안] |
| 큰 체온 숫자 · − / + · 빠른 값 칩 | 0.1° 단위. 범위 34.0~42.0 (저장소 `CLAUDE.md` 규칙) | [원본 유지] |
| 길게 눌러 기록 | 0.7초 누르면 저장. 버튼 글자에 대상과 값이 함께 보임 | 길게 누르기는 [원본 유지], 버튼 안 대상·값 표시는 [신규 제안] |

**저장 상태 [신규 제안]**

| 상태 | 화면 | 누를 수 있는 것 |
|---|---|---|
| 입력 중 | 길게 눌러 기록 | 전부 |
| 저장 중 | "저장 중이에요. 다시 누르지 않아도 돼요" + 돌아가는 표시 | **없음.** 대상·값·닫기·기록 버튼이 모두 잠겨 같은 값이 두 번 저장되지 않음 |
| 성공 | "✓ 이서준 37.8° · 10:21 기록됨" + [별님카드에서 보기] [다음 별님] | 두 버튼, 닫기 |
| 실패 | "저장하지 못했어요. 입력한 값 37.8°와 대상 이서준은 그대로예요. 기록은 아직 남지 않았어요" + [다시 시도] [값 고치기] | 두 버튼, 값 조절 |

- 서버 응답을 받기 전에는 "전송 완료"라고 쓰지 않습니다. 시안은 서버가 없으므로 성공 문구에 "시연용 저장 · 서버로 전송되지 않았어요"를 함께 적습니다.
- 실제 앱에서 "기기에 저장됨"과 "서버에 올라감"을 따로 보여 줄지는 **[팀 확인 필요]** (동기화 방식이 정해져야 함).
- 성공하면: 그 별님의 열려 있던 체온 할 일(재측정)이 완료로 바뀝니다. 저장소 `CLAUDE.md`가 적어 둔 `saveMeasurement`의 "할 일 자동 완료"를 그대로 따른 것이고, 시안이 새로 만든 규칙이 아닙니다 [원본 유지 · 코드 동작은 미검증].
- **읽음 확인은 체온을 저장해도 바뀌지 않습니다.**
- 판정(평소·주의·이상·위험·저온)은 `lib/core/judgment.dart` 하나가 정합니다. 시안은 계산하지 않습니다. 체온을 저장했다고 의료진에게 바로 호출이 가는 규칙도 만들지 않았습니다.

### 3-3. 별님카드 · 아카이브

**답하는 질문:** 평소와 무엇이 달라졌고 예전에는 어땠나?

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 프로필 | 이름 · 나이 · 담임 | [원본 유지] |
| 평소 체온 / 최근 체온 | 제공된 기준값, 최근 측정값·시각·기록자, 최근 추이 선 | [원본 유지] (기준값 계산은 `baseline.dart` 소유) |
| 체온 기록하기 · 대응 이력 #n | 퀵 체온을 이 별님으로 엶 / 대응 기록으로 이동 | 연결은 [신규 제안] |
| **일정 묶음** | 오늘 일정 + 앞으로 14일 안 별님 연결 일정 최대 3건, 읽기 전용 | [신규 제안] · [팀 확인 필요] |
| 검색 · 종류(모두/개인 기록/반 공지) · 기간(전체/오늘/7일) | 부분 일치 검색 | [원본 유지] |
| 새 기록 n건 · 모두 확인 | 눌러야 읽음 처리 | [원본 유지] |
| 타임라인 | 날짜별 묶음. 카드마다 읽음 확인·업무 두 칸 | 두 칸은 [신규 제안] |

| 버튼 | 동작 | 결과 |
|---|---|---|
| 기록 카드의 상세 | 상세 시트 열기 | 상태 변화 없음. 시트 안의 [확인했어요]·[완료했어요]를 눌러야 바뀜 |
| 모두 확인 | 이 별님 기록과 이 반 공지의 읽음 확인을 한 번에 | 업무 완료는 바뀌지 않음 |
| 대응 이력 #n | 그 별님의 대응 기록으로 이동 | — |

빈 상태: "조건에 맞는 기록이 없어요" / "‘검색어’에 맞는 기록이 없어요" / 일정 없음: "오늘과 앞으로 14일 안에 연결된 일정이 없어요".

일정 묶음에서 정할 것 [팀 확인 필요]: 제목·메모에 진단명이 들어갈 수 있는데 모바일에 어디까지 보일지(일정 v2 §6-8), 누르면 어디로 갈지(시안은 이동 없음), 별님카드 시안(`ResidentTimeline`)을 누가 고칠지.

### 3-4. 알림 · 대응 기록

**답하는 질문:** 간호 선생님이 확인했는가? 내가 다음에 할 것은 무엇인가?

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 알림 한 줄 | 반 · 별님 · 시각 · 내용 · "담당자 확인 ✓/전" · "업무 남음/완료" | 목록은 [원본 유지], 상태 칩은 [신규 제안] |
| 일정 알림 | "이서준 별님 치과 검진 (11.28 14:00)" | [신규 제안] (일정 v2 §6-11) |
| 대응 기록 | 상태 네 칸 + 시간순 이력 + [재측정 기록하기] [별님카드] | 네 칸 구분은 [신규 제안] |

| 버튼 | 동작 | 결과 |
|---|---|---|
| 알림 한 줄 | 관련 별님의 대응 기록으로 이동 (일정 알림은 별님카드로) | **알림 읽음만** 바뀜. 담당자 확인·업무 완료·대응 종료는 그대로 |
| 재측정 기록하기 | 퀵 체온을 그 별님으로 엶 | 저장 성공 시 이력에 한 줄 추가, 업무 완료 |

**상태 네 가지 — 시안이 구분해 보여 주는 방식 [팀 확인 필요]**

| 상태 | 누가 바꾸나 | 시안에서 바뀌는 때 |
|---|---|---|
| 알림 읽음 | 나 (생활관 선생님) | 알림을 눌렀을 때 |
| 담당자 확인 | 간호 선생님 (PC 의료 호출함) | 모바일에서 바꾸지 않음. 읽기만 |
| 업무 완료 | 나 | 재측정 체온을 저장했을 때 / [완료했어요]를 눌렀을 때 |
| 대응 종료 | 기존 이상 대응 규칙 | 모바일 시안에서 바꾸지 않음 |

저장소에는 `CaseStatus { unacked, acked, active, waitingRemeasure, closed }`와 `CallStatus { open, done }`이 이미 있습니다. 위 네 칸을 이 값들에 어떻게 맞출지는 통합 담당(용태 님)과 정해야 합니다.

## 4. 공통 규칙

- 같은 기록의 읽음 확인·업무 상태는 인수인계·별님카드·상세·알림이 **하나의 원본**을 같이 봅니다. 시안에서도 한 곳에서 바꾸면 다른 화면에 그대로 보입니다.
- 기록을 지우는 동작은 없습니다 [원본 유지].
- 처방·투약·케어팀 대화 내용은 모바일에 옮기지 않습니다. 결과 상태만 봅니다.
- 접근성: 모든 버튼은 실제 `<button>`, 저장 결과는 화면 읽기 프로그램에 바로 읽히도록 했고, 색만으로 구분하지 않고 글자("✓ 완료", "남음")를 함께 씁니다. 키보드는 Enter로 기록, Esc로 닫기.

## 5. 시연 순서

1. 인수인계 → 이서준 카드 [재측정하기]
2. 퀵 체온: 기록 대상 확인 → + 두 번 → 길게 눌러 기록
3. (옆 안내의 "다음 저장을 실패로 시연"을 켠 경우) 실패 → 입력값 유지 확인 → [다시 시도]
4. 성공 → [이서준 별님카드에서 보기] → 맨 위에 방금 기록, 09:15 기록의 업무가 "완료 (체온 기록)", 읽음 확인은 "아직 안 읽음" 그대로
5. 🔔 → "간호 선생님이 이서준 별님 호출을 확인했어요" → 대응 기록 #102

검수 결과는 `APP_통합메모.md` 4장에 적었습니다.
