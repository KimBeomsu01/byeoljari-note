# 별자리노트 — PC 일정 페이지 기능 명세 v2 (초안)

- 작성일: 2026-11-23
- 대상 코드: `byeoljari-note` 저장소 `v1.01` 브랜치, `lib/features/pc/pc_schedule_*.dart`
- 읽는 사람: 팀장(저장 구조 검토), 일정 화면을 만드는 팀원
- 표시: **[결정]** 담당자가 정함 · **[제안]** 작성자 판단, 고쳐도 됨 · **[확인 필요]** 팀에서 정해야 함

## 1. 한눈에 보기

지금 PC 일정 페이지는 시설 행사 달력이다. 이것을 **노션 캘린더·iCloud 캘린더처럼 열자마자 달력이 뜨고, 바로 넣고, 검색하고, 반·업무별로 켜고 끄는 캘린더**로 바꾼다. 그리고 프로젝트의 최우선 과제인 건강돌봄에 맞춰, **다른 페이지에 이미 있는 건강 자료(재측정·진료 예약·이상 건·근무조)를 달력에서 함께 보고 바로 그 화면으로 넘어갈 수 있게** 한다.

바뀌는 것 세 가지:

1. **화면 뼈대**: 왼쪽(작은 달력 + 캘린더 목록) · 가운데(달력) · 오른쪽(일정 편집 패널).
2. **저장 구조**: 일정에 종료 시각, 며칠짜리, 반복, 대상 별님, 수정·취소 기록이 추가된다. → 7장. **팀장 검토 필요.**
3. **건강 연결**: 자동 캘린더(읽기 전용) + 별님 연결 일정.

## 2. 왜 바꾸나

- [결정] 일정 페이지에서는 **전반적인 일정을 한눈에** 보고 싶다. 지금은 제목·탭·필터 카드가 화면 위쪽을 차지해 달력이 아래로 밀린다.
- [결정] 일정 넣기가 "+ 일정 등록" 창 하나뿐이라 느리다. 달력 칸을 눌러 바로 넣고 싶다.
- [결정] 반 필터가 하나만 고르는 방식이고, 업무 분류는 범례일 뿐 끌 수 없다. 여러 개를 동시에 켜고 끄고 싶다.
- [결정] 매주 되풀이되는 일정을 한 번에 넣고 싶다. 지금은 하루짜리 한 건씩만 저장된다.
- [결정] 프로젝트의 최우선은 건강돌봄 관리다. 일정이 다른 페이지(현황판·의료 호출함·인수인계·별님카드)와 따로 놀지 않아야 한다.

## 3. 목표 · 하지 않는 것 · 피할 것

**목표**
- 페이지를 열면 이번 달 달력이 화면 대부분을 차지한다.
- 월·주·일 보기를 오가도 선택한 날짜가 유지된다.
- 일정 한 건을 넣는 데 누르기 2번 + 제목 입력이면 된다.
- 반·업무·자동 캘린더를 각각 켜고 끌 수 있다.
- 오늘 재측정·진료 예약·열린 이상 건이 달력에 보이고, 누르면 해당 화면이 열린다.
- 병원 방문·검진 같은 일정을 별님에게 붙일 수 있다.

**단계 나누기** [제안] — 담당자가 넣고 싶다고 한 것을 모두 담되, 다른 사람·기관의 결정이 필요한 것은 뒤 단계로 뒀다.

| 단계 | 들어가는 것 | 먼저 필요한 것 |
|---|---|---|
| 1단계 | 달력 뼈대 · 바로 넣기 · 반복 · 켜고 끄기(반 여러 개) · 검색 · 자동 캘린더 · 별님 연결 · 여러 반 대상 일정 · 엑셀 가져오기·내보내기 · 모바일 별님카드에 일정 표시 · 앱 안 알림 | 팀장의 저장 구조 검토 (7장) |
| 2단계 | 하루 일과(식사·목욕 등) 캘린더 · hwpx 가져오기 · 카카오워크 알림 · `.ics` 파일 내보내기 | 혜진원의 실제 일과표 양식, 카카오워크 관리자의 Bot 등록, 서버 수정 |
| 3단계 (조건이 맞으면) | 구글 캘린더 양방향 연동 · 문자 · 기기 푸시 알림 | 서버를 바깥에서 접속할 수 있게 하는 것, 구글·통신사 계정과 비용 |

**하지 않는 것**
- 일정 끌어서 옮기기(드래그) — 후속
- 모바일에 달력 화면을 따로 만드는 것 (v1.01에서 없앴다). 모바일은 알림과 별님카드 안의 일정 표시까지만 (6-13)
- 카카오워크 캘린더에 일정을 직접 넣는 것 — 공개된 API가 없다 (6-11)

**피할 것 (되더라도 실패로 보는 것)**
- 일정 화면에서 체온을 입력하거나 판정하게 되는 것. 체온 입력은 퀵 체온 화면 하나뿐이다.
- 자동 캘린더 자료를 일정 쪽에 복사해 저장하는 것. 두 곳의 값이 어긋난다.
- 일정을 지우면 기록이 사라지는 것.
- 건강 항목이 많아져 일반 일정이 안 보이는 것. 그래서 자동 캘린더는 끌 수 있어야 한다.

## 4. 지켜야 할 제약 (저장소 `CLAUDE.md`)

| 제약 | 이 명세에서의 뜻 |
|---|---|
| 화면은 Claude Design 시안이 기준. 시안에 없는 화면은 만들지 않는다 | 코드보다 **시안(`PcSchedule`)을 먼저 고쳐야** 한다. 시안 수정은 팀 합의 후 |
| 백엔드·DB 구조는 바꾸기 전에 먼저 묻는다 | 7장을 팀장에게 먼저 보여 준다 |
| 기록을 지우는 코드 금지 | 일정 삭제는 없다. **취소**로 남긴다 |
| 체온 입력은 퀵 체온 화면 하나뿐 | 일정에서는 읽기와 이동만 |
| 투약 용량 계산·추천 금지 | 일정에 약 이름을 적을 수는 있어도 계산·추천은 없다 |
| 실제 별님·직원 정보 금지 | 시연 자료는 `seed.dart` 가상 명단만 |
| 시연 DB와 개발 DB의 동작이 같아야 한다 | 새 항목은 모델 JSON → `toSnapshotMap`/`_restore` → 시연 시드 → 개발 DB 예시까지 |
| PC는 폭 1280 기준 | 1280에서 왼쪽 220 · 오른쪽 패널 320을 열어도 달력이 읽혀야 한다 |
| 디자인 토큰 `Ds`·`T`, PC 강조색은 파랑 | 노션의 어두운 화면은 구조만 참고. 색은 지금 밝은 화면 그대로 |

## 5. 검토한 방법

건강돌봄과 엮는 방법 세 가지를 비교했다.

| 방법 | 내용 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| A. 자동 캘린더 | 다른 페이지의 시각 있는 자료를 달력이 읽어서 보여 주기만 한다 | 이중 입력 없음. 저장 구조 안 바뀜 | 달력에서 고칠 수 없다. 미리 잡는 일정은 못 다룬다 |
| B. 별님 연결 일정 | 직접 넣는 일정에 대상 별님을 붙인다. 호출함·현황판에 "일정 잡기" | 병원 방문·검진 등 미리 잡는 건강 일정 | 지금 벌어지는 일(재측정 등)은 안 보인다 |
| **C. A + B** | 자동으로 생기는 일은 A, 사람이 잡는 일은 B | "오늘 건강 관련해서 뭐가 있지"가 한눈에 | 일이 가장 많다 |

**[결정] C안.** 건강돌봄이 최우선이면 두 쪽이 다 필요하다. A는 저장 구조를 안 건드려 부담이 작다.

반복 일정 저장 방법도 두 가지를 봤다.

| 방법 | 내용 | 판단 |
|---|---|---|
| 규칙 하나만 저장 | "매주 화요일, 12월 말까지"를 일정 한 건에 적고 화면에서 펼쳐 그린다 | **[제안] 채택.** 자료가 작고, 고칠 때 한 건만 바꾸면 된다. iCalendar 표준 방식 |
| 미리 다 만들어 저장 | 52주치를 52건으로 저장 | 스냅샷이 커지고, "전체 수정"이 어렵다 |

## 6. 화면과 기능

### 6-1. 화면 뼈대

```
┌──────────────┬───────────────────────────────────────────────┬─────────────┐
│ ‹ 2026년 11월 › │ 2026년 11월     ‹ 오늘 ›   [월|주|일]   🔍   + 일정   ⋯ │ (일정을 눌렀을│
│ 작은 달력       ├───────────────────────────────────────────────┤  때만 열림)   │
│              │  일    월    화    수    목    금    토            │             │
│ 건강 (자동)     │                                               │ 제목          │
│ ◉ 재측정·할 일  │                                               │ 날짜·시간      │
│ ◉ 진료·의료 호출│          달력 (화면 가득)                        │ 반복          │
│ ◉ 이상 건       │          칸을 누르면 그 자리에서 입력               │ 반 · 업무      │
│ ◉ 근무조       │                                               │ 대상 별님      │
│ 반             │                                               │ 담당 · 장소    │
│ ◉ 은하수자리    │                                               │ 메모          │
│ ◉ 물병자리 …    │                                               │             │
│ 업무           │                                               │ [일정 취소]    │
│ ◉ 시설 점검 …   │                                               │             │
└──────────────┴───────────────────────────────────────────────┴─────────────┘
```

- 왼쪽 레일과 맨 위 머리는 지금처럼 `pc_shell.dart`가 그린다. 위 그림은 그 안쪽이다.
- 지금의 3줄짜리 머리 카드(시설 이름·"실시간 스케줄 허브"·큰 제목·저장 상태·근무조 글자)는 없앤다. 달력 위에는 한 줄 도구막대만 둔다.
- 오른쪽 "선택 일과표" 패널은 없앤다. 그 자리는 일정을 눌렀을 때만 열리는 편집 패널이 쓴다.
- [제안] 왼쪽 목록은 접을 수 있다 (노션 캘린더와 같다).

### 6-2. 보기와 이동

| 보기 | 내용 |
|---|---|
| 월 | 6주 격자. 한 칸에 일정 3줄까지, 넘치면 "외 N건"(누르면 그날의 일 보기로) |
| 주 | 7일 × 시간 격자. 맨 위에 종일·며칠짜리 줄 |
| 일 | 하루 × 시간 격자. 종일 줄 포함 |

- 지금의 "목록형 전체보기"는 따로 두지 않고 **검색 결과 목록**이 그 역할을 한다 (6-6).
- `‹` `›`는 보기 단위(달·주·일)만큼 이동한다. "오늘"은 오늘로 돌아온다.
- 왼쪽 작은 달력에서 날짜를 누르면 그 날짜로 이동한다. 일정이 있는 날에는 점이 찍힌다.
- 오늘 날짜는 강조색 동그라미, 주·일 보기에는 지금 시각 선을 긋는다.
- [제안] 단축키: `M` 월 · `W` 주 · `D` 일 · `T` 오늘 · `/` 검색 · `Esc` 패널 닫기. 글자를 입력 중일 때는 동작하지 않는다.

### 6-3. 바로 넣기

1. 월 보기에서 날짜 칸의 빈 곳을 누르면, 그 칸에 제목 입력 줄이 생긴다. 제목을 쓰고 Enter를 누르면 **종일 일정**으로 저장된다.
2. 주·일 보기에서 시간 칸을 누르면 그 시각부터 1시간짜리 일정의 제목 입력 줄이 생긴다.
3. 저장과 동시에 오른쪽 편집 패널이 열려 나머지(반복·반·업무·별님 등)를 이어서 고칠 수 있다. 안 고쳐도 일정은 이미 저장되어 있다.
4. 제목이 비어 있는 채로 Esc나 바깥을 누르면 아무것도 저장되지 않는다.
5. 도구막대의 "+ 일정"은 선택한 날짜로 편집 패널을 빈 상태로 연다.

- 새 일정의 기본값: 반 = 왼쪽에서 하나만 켜져 있으면 그 반, 아니면 시설 전체. 업무 = 시설 점검/행사.

### 6-4. 편집 패널 (오른쪽)

일정을 누르면 열린다. 창(모달)이 아니라 옆 패널이라 달력이 계속 보인다. 고친 내용은 칸을 벗어날 때 바로 저장된다 (저장 버튼 없음).

| 칸 | 내용 |
|---|---|
| 제목 | 필수 |
| 날짜 · 시간 | 시작 날짜, 시작·종료 시각, "종일" 스위치. 종료 날짜를 뒤로 잡으면 며칠짜리 |
| 반복 | 안 함 · 매일 · 매주(요일 여러 개) · 매월 · 끝나는 날(없음 / 날짜) |
| 반 | 시설 전체, 또는 반 하나나 여러 개 |
| 알림 | 없음 · 시작할 때 · 10분 전 · 30분 전 · 하루 전 (6-11) |
| 업무 | 지금 있는 5개: 시설 점검/행사 · 특수교육 · 재활치료 · 생활 케어 · 촉탁의 진료. 색도 지금 그대로 |
| 대상 별님 | 선택. 이름으로 찾아 한 명을 붙인다 (6-8) |
| 담당 · 장소 | 글자 그대로 |
| 메모 | 여러 줄 |
| 맨 아래 | 만든 사람·시각, 마지막으로 고친 사람·시각, [일정 취소] |

- 종료가 시작보다 이르면 저장하지 않고 그 칸 아래에 이유를 보여 준다.
- **일정 취소**: 지우지 않는다. 취소한 일정은 달력에서 사라지고, 왼쪽 목록 맨 아래 "취소한 일정 보기"를 켜면 줄 그은 글씨로 다시 보인다. 취소를 되돌릴 수 있다.
- **반복 일정을 고치거나 취소할 때**는 범위를 묻는다: "이 일정만" · "이 일정과 이후 모두" · "전체".
- 자동 캘린더 항목을 누르면 편집 패널 대신 **읽기 전용 요약**과 "○○에서 열기" 버튼이 나온다 (6-7).

### 6-5. 캘린더 켜고 끄기 (왼쪽 목록)

- 세 묶음이다: **건강(자동)** · **반** · **업무**. 줄마다 색 점과 눈 아이콘이 있고, 누르면 켜지고 꺼진다.
- 일정이 보이는 조건: (일정의 반이 켜져 있다 **또는** 시설 전체 일정이다) **그리고** (일정의 업무가 켜져 있다). 자동 캘린더는 종류별로 따로 켜고 끈다.
- [제안] 줄 이름을 길게 누르거나 "이것만 보기"를 누르면 그 줄만 남기고 같은 묶음의 나머지를 끈다.
- 반 이름 옆의 "(중증 N명)" 표시는 유지한다.
- 반은 여러 개를 동시에 켤 수 있다 [결정]. 일정 하나가 여러 반을 대상으로 할 수도 있다 (편집 패널의 반 칸에서 여러 개 선택). 그 일정은 대상 반 중 하나라도 켜져 있으면 보인다.
- [제안] 켜고 끈 상태는 그 브라우저에만 기억한다 (서버에 저장하지 않음). 처음에는 모두 켜져 있다.
- 일정 색은 **업무** 색을 따른다 (지금과 같다). 반은 색이 아니라 일정 줄의 반 이름 글자로 구분한다.

### 6-6. 검색

- 도구막대의 🔍를 누르면 입력 줄이 열리고, 달력 자리에 결과 목록이 날짜순으로 나온다.
- 찾는 범위: 제목 · 담당 · 장소 · 메모 · 반 이름 · 대상 별님 이름. 부분 일치.
- [제안] 기간: 오늘 기준 앞뒤 1년. 반복 일정은 그 기간 안의 날짜로 펼쳐서 찾되, 같은 반복은 "매주 화 · 다음 11월 24일"처럼 한 줄로 묶는다.
- 꺼 둔 캘린더의 일정도 결과에 나온다 (흐리게, "꺼 둔 캘린더" 표시). 못 찾는 것보다 낫다.
- 결과를 누르면 그 날짜로 달력이 이동하고 편집 패널이 열린다. Esc로 검색을 닫으면 보던 달력으로 돌아온다.
- 결과가 없으면 "조건에 맞는 일정이 없어요".

### 6-7. 자동 캘린더 — 건강 자료 읽어 오기

일정 쪽에는 아무것도 저장하지 않는다. 달력을 그릴 때 저장소(`InMemoryRepository`)에서 읽는다. 모두 읽기 전용이고, 누르면 요약과 이동 버튼이 나온다.

| 캘린더 | 읽는 자료 | 달력에 보이는 모습 | 누르면 |
|---|---|---|---|
| 재측정·할 일 | 이상 건의 재측정 예정 시각 (`Case.remeasureAt`), 인수인계 글에 붙은 할 일의 기한 (`Entry.task`의 `dueAt`. 체온·메모 두 종류 모두) | "재측정 · 이서준" 14:30. 끝난 것은 ✓와 흐린 글씨, 기한이 지났는데 안 끝난 것은 "지남" 표시 | 패널에 요약(별님·기한·상태·글 내용). 이상 건이 있으면 [별님 상태 열기] |
| 진료·의료 호출 | 화상 진료 예약 시각 (`MedicalCall.videoAt`) | "화상 진료 · 이서준" 10:20. 끝난 호출(`done`)은 ✓와 흐린 글씨 | [의료 호출함에서 열기] |
| 이상 건 | 이상 건이 열린 시각~닫힌 시각 (`Case.createdAt`~`closedAt`) | 열린 날부터 닫힌 날까지 이어지는 종일 띠. 아직 열려 있으면 오늘까지. "이상 대응 중 · 이서준" | [별님 상태 열기] |
| 근무조 | 근무조 시작·종료 (`Shift.startAt`~`endAt`) | 주·일 보기에서 옅은 배경 띠와 교대 시각 선. 월 보기에는 그리지 않는다 | 근무조 이름·근무자 요약만 |

**누르면 어디로 가나 (코드 확인 결과)**
- 의료 호출: 이미 길이 있다. 현황판이 쓰는 `selectedCallProvider.select(id)` + `pcPageProvider.go(PcPage.calls)`를 그대로 쓴다.
- 이상 건·별님: PC에는 이상 건 상세 화면이 없다. `routes.dart`의 `openCaseDetail`·`openResidentCard`는 모바일 화면을 띄우는 것이라 PC에서는 쓰지 않는다. **[제안]** 현황판이 쓰는 별님 상태 창(`showResidentStatus`, `pc_dashboard_dialogs.dart`)을 연다. 시안에 없는 화면을 새로 만들지 않는다.
- 인수인계 글: PC에 글 하나를 여는 화면이 없다. 이동 없이 패널에 글 내용을 요약해 보여 준다.

**자료를 읽을 때 주의할 점 (코드 확인 결과)**
- **재측정은 두 군데서 생긴다.** 주의 단계는 체온을 저장할 때 `Task(dueAt: +30분, auto: true)`가 만들어지고, 이상 건은 `scheduleRemeasure`가 `Case.remeasureAt`을 적는다. **[제안]** 같은 별님의 두 항목이 5분 안에 겹치면 이상 건 쪽 한 줄만 그린다.
- **할 일은 따로 목록이 없다.** 인수인계 글(`Entry`)마다 0~1개 붙어 있어서 글을 훑어야 한다.
- **기한 표시**: `dueAt`이 있으면 그 시각에 그리고 `duePreset`('다음 근무조' 등)은 이름표로 덧붙인다. `dueAt` 없이 `duePreset`만 있으면 그날 종일 줄에 그린다.
- **근무조는 저장된 자료가 아니다.** `shiftsAround(at)`가 매일 같은 틀(오전 07–15 · 오후 14–22 · 야간 22–07)로 그때그때 만들어 내고, 범위가 앞뒤 하루뿐이다. 주 보기에 쓰려면 기간으로 받아 오는 함수를 새로 만들어야 한다. 과거·미래 날짜도 같은 틀로 그린다. 겹치는 14–15시는 두 띠를 겹쳐 그리고, 야간은 자정에서 나눠 그린다. 날짜별 근무자 차이는 지금 자료에 없다.

- 판정 단계 이름과 색(평소·주의·이상·위험·저온)은 다른 화면과 같은 것을 쓴다. 색만으로 구분하지 않고 기호와 글자를 함께 쓴다.
- 자동 항목도 6-5의 반 켜고 끄기를 따른다 (그 별님의 반 기준).
- 자동 항목은 검색 대상에 넣는다 (별님 이름으로 찾을 수 있게).
- "체온 측정 시점"은 자동 캘린더로 따로 두지 않는다. 2단계의 하루 일과에 붙여서 보여 준다 (6-14). 지금 측정 시점은 가상 일과(`seed.scheduleFor`)에서 나오므로 1단계에서는 근거 자료가 없다.

### 6-8. 별님 연결 일정

- 일정에 **대상 별님 한 명**을 붙일 수 있다. 붙이면 일정 줄에 별님 이름이 보이고, 반은 그 별님의 반으로 맞춰진다.
- 쓰임: 병원 방문, 건강검진, 촉탁의 진료 예약, 보호자 면회, 개별 치료.
- 편집 패널의 별님 이름을 누르면 현황판과 같은 별님 상태 창이 열린다 (`showResidentStatus`). 모바일용 `openResidentCard`는 PC에서 쓰지 않는다.
- 반은 별님을 붙이는 순간 그 별님의 반으로 정해지고, 별님이 붙어 있는 동안에는 반 칸을 손으로 바꿀 수 없다. 나중에 별님이 반을 옮겨도 이미 만든 일정의 반은 따라가지 않는다 **[제안]**.
- **별님카드에 "다가오는 일정" 표시** [제안]: 그 별님에게 붙은, 오늘부터 14일 안의 일정을 최대 3건 보여 준다. 누르면 PC에서는 일정 페이지의 그 날짜로 간다. 모바일 별님카드에는 읽기 전용으로만 보인다. → 별님카드 담당과 정할 것.
- **다른 화면에서 일정 잡기** [제안]: 의료 호출함의 호출 상세, 현황판의 별님 옆 패널에 "일정 잡기" 버튼. 누르면 일정 페이지가 열리고 편집 패널에 별님·반·업무(촉탁의 진료)가 채워져 있다. → 호출함·현황판 담당과 정할 것. 지금은 일정 페이지의 날짜·보기가 화면 안에만 들어 있어서(`_PcSchedulePageState`), 밖에서 "이 날짜로, 이 내용을 채워서 열기"를 하려면 호출함의 `selectedCallProvider` 같은 provider를 새로 만들어야 한다.
- 민감한 내용: 일정 제목·메모에 진단명 등을 쓸 수 있으므로, 별님 연결 일정은 PC 화면에 로그인한 직원에게만 보인다. 모바일 별님카드에 얼마나 보여 줄지는 **[확인 필요]**.

### 6-10. 엑셀 · hwpx 가져오기와 내보내기

도구막대 `⋯` 메뉴에 "파일에서 가져오기"와 "파일로 내보내기"를 둔다.

**가져오기 (올리기 → 표 확인 → 반영)**
1. 파일을 고른다. 1단계는 `.xlsx`, 2단계에 `.hwpx`를 더한다.
2. 읽은 내용이 표로 나온다: 날짜 · 시작 · 종료 · 일정명 · 반 · 대상 별님 · 업무 · 장소 · 담당 · 반복. 줄마다 고치거나 뺄 수 있다.
3. 문제가 있는 줄은 이유와 함께 표시한다: 날짜가 아님, 종료가 시작보다 이름, 없는 반·별님 이름, 같은 이름의 별님이 둘(직접 고르게 한다), 이미 있는 일정과 겹침.
4. "일정에 반영"을 눌러야 저장된다. 그 전에는 달력이 바뀌지 않는다. 반영 뒤 "N건 넣음 · M건 뺌"을 보여 준다.
5. 가져온 일정에는 어느 파일에서 왔는지 남긴다 (`sourceFile`). 잘못 올렸으면 "이 파일에서 온 일정 모두 취소"를 할 수 있다.

- 엑셀은 **정해진 열 양식**만 읽는다. 양식 파일은 "양식 내려받기"로 받는다. 내보낸 파일을 그대로 다시 가져올 수 있어야 한다.
- 파일은 브라우저 안에서 읽는다. 서버에 올리지 않는다 (서버를 고치지 않아도 된다).
- **hwpx (2단계)**: hwpx는 압축된 XML이라 표를 읽을 수는 있다. 다만 일과표 양식이 기관마다 달라서 **혜진원이 실제로 쓰는 양식을 받아야** 읽는 규칙을 만들 수 있다. 양식을 못 알아보면 "이 양식은 아직 읽지 못해요. 엑셀 양식으로 올려 주세요"를 보여 준다. 예전 `.hwp`(압축 XML이 아닌 것)는 지원하지 않는다. AI로 자동 변환하는 것은 넣지 않는다. **[확인 필요]** 혜진원 양식 견본.
- 실제 양식 견본에는 실제 별님 이름이 들어 있을 수 있다. 저장소에 올리지 않는다.

**내보내기**
- 기간과 캘린더(반·업무)를 골라 `.xlsx`로 받는다. 반복 일정은 날짜별로 펼친 줄로 나온다. 취소한 일정은 빼는 것이 기본이다.
- 건강 자동 캘린더 항목은 기본으로 빼고, 넣으려면 따로 체크한다. 내보낼 건수를 먼저 보여 준다.
- `.ics` 내보내기 (2단계): 같은 범위를 캘린더 표준 파일로 받는다. 구글·Apple 캘린더에서 "가져오기"로 열 수 있다. 한 번 가져가는 것이고 계속 맞춰지지는 않는다.

### 6-11. 알림과 카카오워크

**앱 안 알림 (1단계)**
- 모바일에는 이미 알림 모음(`notice_center.dart`)이 있다. 여기에 일정 알림 종류를 더한다.
- 알리는 일정: 내 담당 반의 별님에게 붙은 일정, 내 담당 반 일정 중 "알림"을 켠 것. 시설 전체 일정은 "알림"을 켠 것만.
- 편집 패널에 "알림" 칸을 더한다: 없음 · 시작할 때 · 10분 전 · 30분 전 · 하루 전. 기본은 별님 연결 일정이 30분 전, 나머지는 없음.
- 앱이 열려 있을 때만 뜬다. 앱을 닫아 둔 폰에는 가지 않는다 — 그건 카카오워크 알림이나 기기 푸시가 맡는다.

**카카오워크 (2단계)** — 공식 문서로 확인한 것 (9-7)
- 카카오워크에는 Bot이 대화방이나 직원에게 **메시지를 보내는** API가 있다 (`messages.send`, `messages.send_by_email`). 관리자 화면에서 Bot을 만들면 App Key가 나온다.
- **캘린더 API는 문서에 없다.** 그래서 카카오워크 캘린더에 일정을 넣는 연동은 할 수 없고, "일정 알림을 카카오워크 메시지로 보내기"까지가 가능한 범위다.
- 보내는 것 [제안]: ① 매일 아침 "오늘 일정" 요약을 지정한 대화방에 ② 알림을 켠 일정의 시작 전 알림 ③ 일정이 바뀌거나 취소됐을 때.
- 필요한 것:
  - 혜진원 카카오워크 관리자가 Bot을 만들고 App Key와 보낼 대화방을 정해 줘야 한다. **[확인 필요]**
  - **서버를 고쳐야 한다.** 지금 서버는 스냅샷을 통째로 저장만 하고 일정 내용을 모른다. 정해진 시각에 스냅샷을 읽어 메시지를 보내는 기능이 새로 필요하다. 서버가 바깥 인터넷(카카오워크 API)으로 나갈 수 있어야 한다. → 팀장과 상의 (7-5).
  - App Key는 `backend/.env`에만 둔다. 저장소에 올리지 않는다.
- **개인정보**: 카카오워크로 보낸 내용은 우리 시스템 밖에 남는다. 메시지에는 일정 제목·시각·반까지만 넣고, **체온·판정·진단·메모는 넣지 않는다.** 별님 이름을 넣을지는 혜진원과 정한다 **[확인 필요]**. 문제정의서에서 카카오워크의 한계로 "올린 사람만 알고 별님별로 묶이지 않는다"가 나왔으므로, 메시지는 알려 주기만 하고 자세한 내용은 앱에서 보게 한다.
- 시연·개발 DB에서는 실제로 보내지 않고 "보낼 내용 미리보기"만 보여 준다.

**문자 · 기기 푸시 (3단계)**
- 문자는 건당 비용과 발신번호 등록이 필요하다. 기기 푸시는 웹이면 HTTPS와 서비스 워커, 설치형 앱이면 구글·Apple 푸시 서비스 연결이 필요하다. 지금 서버는 유니스트 네트워크 안에서만 열려 있어 둘 다 조건이 안 맞는다.

### 6-12. 구글 캘린더 등 외부 캘린더

| 방법 | 되는가 | 이유 |
|---|---|---|
| `.ics` 파일로 내보내 가져가기 | 2단계에 가능 | 파일을 주고받는 것이라 서버 조건이 없다 |
| 구독 주소 (외부 캘린더가 우리 서버에서 주기적으로 읽어 감) | 지금은 안 됨 | 서버가 유니스트 네트워크 안에서만 열려 있어 구글이 접속할 수 없다 |
| 양방향 연동 | 3단계, 조건부 | 구글 클라우드 프로젝트, 직원별 구글 로그인 동의, 서버 수정이 필요하다. 별님 연결 일정이 개인 구글 계정으로 나가는 문제도 있다 |

- 외부로 내보낼 때는 별님 연결 일정과 건강 자동 항목을 기본으로 뺀다.
- **[확인 필요]** 혜진원이 구글 캘린더를 실제로 쓰는지. 안 쓴다면 3단계는 하지 않아도 된다.

### 6-13. 모바일

모바일에 달력 화면은 만들지 않는다. 두 가지만 한다.

1. **별님카드 안에 일정 표시**: 별님카드에 "일정" 묶음을 더한다. 오늘 그 별님의 일정(2단계부터는 하루 일과 포함, 지금 하는 것 강조)과 앞으로 14일 안의 별님 연결 일정(병원 방문 등) 최대 3건을 보여 준다. 읽기 전용이고, 고치는 것은 PC에서 한다.
2. **알림**: 6-11의 앱 안 알림이 알림 모음에 뜬다. 누르면 그 별님카드가 열린다.

- 모바일은 내 담당 반만 보이는 규칙(`repo.myClasses`)을 그대로 따른다.
- 별님카드는 시안에 있는 화면이라 새 화면을 만드는 것은 아니지만, 묶음이 하나 늘어나므로 **시안(`ResidentTimeline`)을 먼저 고쳐야 한다.** → 별님카드 담당과 정할 것.

### 6-14. 하루 일과 (식사 · 목욕 등) — 2단계

별님의 하루 일과를 달력에서 볼 수 있게 한다.

- **저장**: 일과도 일정 한 건이다. 새 저장 구조의 반복 + 반 또는 별님 연결을 그대로 쓴다. 예: "점심 식사 · 매일 12:00 · 은하수자리", "온수 목욕 · 매주 화·금 15:00 · 이서준". 업무 분류에 **"일과"**를 하나 더하고, 세부 종류는 코드에 이미 있는 6가지(식사·학교·치료/교육·예체능·목욕·생활, `ScheduleKind`)를 쓴다.
- **보이는 방식**: 일과는 수가 많아서(36명 × 하루 여러 건) 그대로 그리면 달력이 묻힌다.
  - 왼쪽 목록의 "일과" 캘린더는 **처음에는 꺼져 있다.**
  - 월 보기에서는 일과를 그리지 않는다. 주·일 보기에서만 그린다.
  - **별님 한 명 보기**: 왼쪽 목록 위의 "별님 찾기"에서 한 명을 고르면, 달력이 그 별님의 것만 보여 준다 — 그 별님의 일과, 그 반의 일과, 별님 연결 일정, 그 별님의 건강 자동 항목. 일 보기가 곧 "별님 한 명의 하루 일과표"가 된다. 고른 별님은 도구막대에 이름표로 보이고 ×로 푼다.
- **체온 측정 시점과 잇기**: 일과 한 건에 "체온 측정 시점"(오전 · 오후 목욕 전 · 오후 귀가 후, `TempSlot`)을 붙일 수 있다. 붙어 있으면 그 줄에 "오전 체온 ✓ 36.5 평소 / 미기록 / 예정"이 함께 보인다. 값과 판정은 읽기만 한다. 6-7에서 미뤘던 "체온 측정 시점 자동 캘린더"는 이것으로 대신한다.
- **넣는 방법**: 하나씩 넣기에는 많다. 그래서 가져오기(6-10)와 같은 단계에 둔다. 일과표 파일을 올려 반복 일정으로 한 번에 넣는다.
- **지금 코드와의 관계**: 지금 코드에 남아 있는 일과(`scheduleOf`)는 저장된 자료가 아니라 시드가 규칙으로 만들어 내는 가상 자료다(`seed.scheduleFor`). 2단계에서 이것을 저장된 일정으로 바꾸고, 시연 DB 시드가 같은 내용을 반복 일정으로 채우게 한다. 측정 시점 계산(`slotStatuses`)도 이 자료를 읽도록 바뀐다 → 퀵 체온·인수인계 담당과 맞춰야 한다.
- **[확인 필요]** 혜진원의 실제 일과가 반 단위인지 별님 단위인지, 통학하는 별님의 일과가 어떻게 다른지.

## 7. 저장 구조 변경안 — 팀장 검토 요청

### 7-1. 지금

일정 한 건은 `CalendarEvent` (`lib/core/models.dart`)이고, 계정별 스냅샷 JSON의 `calendar` 배열에 들어 있다.

지금 항목: `id` · `date`(날짜) · `time`('HH:mm', 없으면 종일) · `title` · `category`(5종) · `classId`(없으면 시설 전체) · `owner` · `detail` · `holiday` · `createdBy` · `createdAt`

쓰기 동작은 `addCalendarEvent` 하나뿐이다. 고치기·취소가 없다.

### 7-2. 추가하려는 항목

모두 **없어도 되는 항목**이다. 기존 일정은 이 항목들이 비어 있는 채로 지금과 똑같이 읽힌다.

| 항목 | 형식 · 예 | 용도 |
|---|---|---|
| `endTime` | `'11:00'` | 끝나는 시각. 없으면 시작 + 1시간으로 그린다 |
| `endDate` | `'2026-11-27'` | 며칠짜리 일정의 마지막 날. 없으면 하루 |
| `place` | `'2층 물리치료실'` | 장소 |
| `residentId` | `'r_012'` | 대상 별님 |
| `repeat` | 아래 7-3 | 반복 규칙 |
| `exceptions` | 아래 7-3 | 반복에서 빠지거나 바뀐 날 |
| `splitFrom` | `'cal-12'` | "이 일정과 이후 모두"로 갈라져 나온 경우 원래 일정의 id |
| `classIds` | `['c_1','c_3']` | 여러 반 대상 일정. 있으면 `classId`보다 먼저 본다. 반 하나짜리는 지금처럼 `classId`만 쓴다 |
| `remind` | `'30m'` | 알림: 없음 · `0` · `10m` · `30m` · `1d` (6-11) |
| `sourceFile` | `{name, at, by}` | 파일에서 가져온 일정일 때 (6-10) |
| `routineKind` | `'bath'` | 2단계. 일과의 세부 종류 6가지 (6-14) |
| `tempSlot` | `'pmBath'` | 2단계. 이 일과에 붙은 체온 측정 시점 (6-14) |
| `updatedBy`, `updatedAt` | | 마지막으로 고친 사람·시각 |
| `cancelledBy`, `cancelledAt` | | 취소한 사람·시각. 있으면 취소된 일정 |

- 종일 여부는 지금처럼 `time`이 없는 것으로 나타낸다. 항목을 따로 만들지 않는다.
- 시각은 지금처럼 `'HH:mm'` 글자로 둔다.

### 7-3. 반복 규칙

```json
"repeat": { "freq": "weekly", "interval": 1, "weekdays": [2, 4], "until": "2026-12-31" }
"exceptions": [
  { "date": "2026-12-01", "cancelled": true },
  { "date": "2026-12-08", "time": "15:00", "endTime": "16:00", "title": "물리치료 (시간 변경)" }
]
```

- `freq`: `daily` · `weekly` · `monthly`. `interval`: 몇 번에 한 번(기본 1). `weekdays`: 1(월)~7(일), 매주일 때만. `until`: 마지막 날(없으면 계속).
- 일정의 `date`가 반복의 첫날이다.
- 예외 한 건은 "그 날짜의 일정을 뺀다"거나 "그 날짜만 일부 항목을 바꾼다"는 뜻이다.
- 한 날짜만 바꿀 수 있는 항목은 시각·제목·장소·담당·메모다. 반·별님·반복 규칙은 "전체"나 "이후 모두"로만 바꾼다 [제안].
- 예외에도 누가·언제 했는지(`by`, `at`)를 적는다. 한 날짜 취소는 그 예외를 `cancelled: false`로 바꿔 되돌린다 (지우지 않는다).
- "이후 모두"로 갈라질 때, 갈라지는 날짜 이후의 예외는 새 일정 쪽으로 옮긴다.
- 고치는 범위별 동작:

| 범위 | 저장 방식 |
|---|---|
| 이 일정만 | `exceptions`에 그 날짜 한 건 추가 |
| 이 일정과 이후 모두 | 원래 일정의 `until`을 전날로 줄이고, 새 일정을 만들어 `splitFrom`에 원래 id를 적는다 |
| 전체 | 일정 본문을 고친다 |

- 매월 반복인데 그 달에 해당 날짜가 없으면(31일 등) 그 달은 건너뛴다.
- iCalendar 표준(RFC 5545)의 RRULE·EXDATE·RECURRENCE-ID와 같은 생각이다. 나중에 외부 캘린더로 내보낼 때 그대로 옮길 수 있다.

### 7-4. 쓰기 동작 (저장소 메서드)

| 메서드 | 하는 일 |
|---|---|
| `addCalendarEvent` (있음) | 새 항목을 받도록 넓힌다 |
| `updateCalendarEvent` (새로) | 일정 본문 고치기. `updatedBy`·`updatedAt` 기록 |
| `cancelCalendarEvent` / `restoreCalendarEvent` (새로) | 취소·되돌리기 |
| `editOccurrence` (새로) | 반복의 한 날짜만 고치기·빼기 |
| `splitSeries` (새로) | "이 일정과 이후 모두" |
| `calendarBetween(from, to)` (새로) | 기간 안의 일정을 반복까지 펼쳐서 돌려준다. 지금의 `calendarOn(day)`도 이것을 쓴다 |

자동 캘린더는 새 저장 항목이 없다. `cases` · `entries`의 할 일 · `calls` · 근무조를 읽기만 한다. 다만 읽는 함수는 새로 필요하다: 기간 안의 근무조, 기간 안의 할 일·재측정·진료 예약·이상 건.

화면 쪽에는 "일정 페이지를 이 날짜로, 이 내용을 채워서 열기"를 위한 provider가 하나 새로 필요하다 (6-8).

### 7-5. 팀장님께 여쭤볼 것

1. **스냅샷 `schema` 번호를 그대로 2로 둬도 되는지.** `schema`가 2가 아니면 자료를 새로 채우게 되어 있어서, 번호를 올리면 기존 자료가 초기화된다. 항목 추가만이므로 **번호를 올리지 않는 것을 제안**한다.
2. **서버(`backend/server.dart`)는 고칠 것이 없다고 보는데 맞는지.** 서버는 스냅샷을 통째로 저장하므로 일정 항목이 늘어도 서버 코드와 DB 표는 그대로다.
3. **예전 화면 빌드가 새 항목을 지우는 문제 — 가장 중요.** 코드로 확인했다. `CalendarEvent.fromJson`은 아는 항목만 읽고 `toJson`은 아는 항목만 쓴다. 그리고 무엇을 저장하든 스냅샷 전체를 다시 올린다. 그래서 **예전 빌드가 열려 있는 탭이나 캐시된 웹 빌드, 예전 설치형 앱이 아무거나 하나 저장하면 반복·취소·별님 연결 항목이 조용히 사라진다.** 서버의 `build/web`만 바꿔서는 막을 수 없다. 방법 후보: (가) 서버가 최소 빌드 번호를 확인해 예전 빌드의 저장을 거절하고 새로고침을 안내한다 — 서버 코드를 조금 고쳐야 한다. (나) 배포 때 모든 사용자를 한 번 로그아웃시키고 설치형 앱도 같이 올린다 — 코드는 안 고치지만 사람이 챙겨야 한다. 어느 쪽으로 할지.
4. **반복 일정이 많아질 때 속도.** 달력을 그릴 때마다 반복을 펼친다. 시설 규모(6반 36명)에서는 문제없을 것으로 보지만, 4초마다 동기화할 때 다시 그리는 범위를 확인해야 한다.
5. **취소한 일정을 언제까지 둘지.** 지우지 않으므로 계속 쌓인다. 스냅샷 크기에 문제가 되는지.
6. **누가 고칠 수 있는지.** 제안: PC 화면에 로그인한 직원은 누구나 넣고 고칠 수 있고, 고친 사람이 기록된다. 의료진 포털(`/doctor`)에서는 일정 페이지를 보여 주지 않는다 (지금과 같다).
7. **카카오워크 알림을 위한 서버 수정 (2단계).** 서버가 정해진 시각에 스냅샷의 일정을 읽어 카카오워크 API로 메시지를 보내야 한다. 서버가 스냅샷 내용을 들여다보는 첫 기능이다. 서버가 바깥 인터넷으로 나갈 수 있는지, 이 방향이 괜찮은지 (6-11).
8. **하루 일과를 저장된 일정으로 바꾸는 것 (2단계).** 지금 `scheduleOf`·`slotStatuses`는 시드가 만들어 내는 가상 일과를 쓴다. 이것을 저장된 반복 일정으로 바꾸면 퀵 체온·인수인계의 측정 시점 계산도 영향을 받는다 (6-14). 일과가 들어가면 일정 건수가 크게 늘어 4번(속도)도 다시 봐야 한다.

### 9-3. 반복 일정 (6-4, 7-3)

| 참고 | 확인한 내용 | 주소 |
|---|---|---|
| 구글 캘린더 | 반복 일정을 고칠 때 "이 일정" · "이 일정 및 향후 일정" · "모든 일정" 중에서 고른다 | https://support.google.com/calendar/answer/37115 |
| Apple 캘린더 | 반복 옵션과 끝나는 시점을 정한다. 지울 때 "이 일정만" · "이후 모든 일정" · "전체" 중에서 고른다 | https://support.apple.com/guide/calendar/set-up-all-day-multiday-or-repeating-events-icl1018/mac |
| RFC 5545 (iCalendar 표준) | §3.3.10 반복 규칙(FREQ 필수, INTERVAL 기본 1, BYDAY 요일 목록, UNTIL은 그날 포함) · §3.8.5.1 EXDATE(뺄 날짜) · §3.8.4.4 RECURRENCE-ID(특정 회차 가리키기) · §3.2.13 RANGE=THISANDFUTURE("이 일정과 이후") | https://www.rfc-editor.org/rfc/rfc5545 |

- 반복 종류를 매일·매주·매월로만 둔 것은 돌봄시설용 도구(StoriiCare)도 그 정도만 쓰기 때문이다.

## 10. 다 됐는지 보는 기준

- 페이지를 열면 이번 달 달력이 1280 폭에서 화면 높이의 대부분을 차지한다.
- 월 → 주 → 일로 바꿔도 선택한 날짜가 같다.
- 월 보기 빈 칸을 누르고 제목을 써서 Enter를 누르면 그 날짜에 종일 일정이 생기고, 새로고침해도 남아 있다.
- "매주 화·목, 12월 31일까지" 일정을 넣으면 해당 날짜에 모두 보이고, 스냅샷에는 한 건만 저장된다.
- 반복 일정의 하루를 "이 일정만" 취소하면 그날만 사라진다. "이후 모두"로 시각을 바꾸면 그 전 날짜는 그대로다.
- 일정을 취소해도 스냅샷에 남아 있고, "취소한 일정 보기"에서 되돌릴 수 있다.
- 반 하나와 업무 하나를 끄면 해당 일정만 사라지고, 시설 전체 일정은 남는다.
- 별님 이름으로 검색하면 그 별님에게 붙은 일정과 자동 항목(재측정·진료)이 나온다.
- 시연 DB에서 재측정 대기 중인 이상 건이 달력의 그 시각에 보이고, 누르면 이상 건 상세가 열린다. 화상 진료 예약도 같다.
- 자동 캘린더를 끄면 그 항목만 사라진다. 스냅샷의 `calendar`에는 자동 항목이 들어가지 않는다.
- v1.01에서 만든 기존 일정이 그대로 보인다.
- 시연 DB와 개발 DB에서 동작이 같다. 개발 DB가 비어 있으면 예시가 흐리게 보인다.
- `flutter test`, `flutter analyze` 통과. 일정 위젯 테스트에 바로 넣기·반복·취소·켜고 끄기가 들어 있다.

## 11. 팀에서 정할 것

1. 7-5의 여섯 가지 (팀장).
2. Claude Design 시안 `PcSchedule`을 이 명세대로 고칠지, 누가 고칠지. 시안이 고쳐져야 코드를 시작하는지, 이 명세로 먼저 만들어도 되는지.
3. 별님카드에 "다가오는 일정"을 넣을지 (별님카드 담당).
4. 의료 호출함·현황판에 "일정 잡기" 버튼을 넣을지 (각 담당).
5. 체온 측정 시점을 자동 캘린더에 넣을지 (6-7).
6. 별님 연결 일정을 모바일에서 얼마나 보여 줄지.
7. 업무 분류 5개가 혜진원 실제 업무와 맞는지. 분류를 직접 만들 수 있게 할지는 이번 범위 밖.
8. 드래그로 일정 옮기기를 언제 할지.
9. 단계 나누기(3장)가 괜찮은지. 특히 엑셀을 1단계에, 하루 일과·hwpx·카카오워크를 2단계에 둔 것.
10. 혜진원에 여쭤볼 것: 실제 일과표 양식 견본(hwpx·엑셀), 카카오워크 관리자가 Bot을 만들어 줄 수 있는지와 알림을 받을 대화방, 메시지에 별님 이름을 넣어도 되는지, 구글 캘린더를 쓰는지, 일과가 반 단위인지 별님 단위인지.
