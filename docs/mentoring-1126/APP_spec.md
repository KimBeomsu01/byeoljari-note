# 별자리노트 · 모바일 앱 기능명세 (APP_기능명세)

- 담당: 어플(범수) · 작성일: 2026-11-26 (통합 시연판 기준으로 다시 씀)
- 대상 사용자: 생활관 선생님 (휴대폰) · 시연 계정: 이수진 담임복지사, 은하수자리
- 짝 파일: `web/mentoring/index.html`(통합 시연 앱의 왼쪽 휴대폰 화면), `APP_integration_memo.md`(통합메모), `APP_real_app_plan.md`(실제 앱 반영 작업서)
- 표시: **[원본 유지]** 기존 화면·규칙 그대로 · **[신규 제안]** 이번에 더한 것 · **[팀 확인 필요]** 팀이 정해야 함

> **범위.** 통합 시연 앱 안의 어플 화면과 그 동작 규칙입니다. 실제 Flutter 코드 반영, 휴대폰 설치, 서버 동기화는 하지 않았습니다. 저장은 이 브라우저 안에만 남습니다. 이름·체온·일정은 모두 가상입니다.
>
> **의료 규칙.** 새로 만들지 않았습니다. 판정 단계와 기준 숫자, 체온 저장 뒤에 일어나는 일은 저장소 `v1.01`의 `judgment.dart`·`repository.dart`를 그대로 옮겼습니다. `judgment.dart`에는 숫자가 “[초안], 간호사 확인 전까지 바뀔 수 있다”고 적혀 있고, 이 시연도 그 상태를 그대로 따릅니다.

## 1. 작업 범위 (5줄)

1. 생활관 선생님의 한 흐름을 잇는다: 인수인계 → 별님 선택 → 퀵 체온 → 저장 결과 → 같은 별님의 카드·아카이브.
2. 알림에서 관련 별님의 대응 기록으로 바로 간다.
3. 개선은 세 가지: 저장 상태(저장 중·성공·실패), 별님별 기록 연결, 읽음 확인과 업무 완료의 구분.
4. 일정은 모바일 달력을 만들지 않고 별님카드 안 읽기 전용 요약만 둔다 (일정 v2 §6-13).
5. 현황판·간호 선생님 호출함·의료진 포털·일정과 **같은 데이터**를 쓴다. 어플은 그 화면들을 고치지 않는다.

## 3. 화면별 명세

### 3-1. 인수인계 — “지금 내가 챙길 별님과 남은 일이 무엇인가?”

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 보기 전환 | 최신 기록 / 별님별(내 담당 반) | [원본 유지] |
| 요약 카드 | 미확인 n · 할 일 n · 체온 미기록 n | [원본 유지], 미확인과 할 일을 따로 세는 것은 [신규 제안] |
| 필터 칩 | 모두 · 미확인 · 할 일 | [원본 유지] |
| 기록 카드 | 반 · 별님 · 작성자·시각 · 체온(평소 대비 차이) · 판정 · 내용 | [원본 유지] |
| 상태 두 칸 | **읽음 확인**(아직 안 읽음 / 내가 확인함) · **업무**(○○ 남음 / 대응 중 / 완료 / 할 일 없음) | [신규 제안] |

| 버튼 | 동작 | 결과 | 실패·예외 |
|---|---|---|---|
| 별님 이름 | 그 별님의 별님카드로 이동 | 뒤로 가면 인수인계 | — |
| 확인했어요 | 그 기록의 **읽음 확인만** 바꿈 | 미확인 −1. 업무는 그대로. 현황판 “인계 확인율”이 올라감 | 실제 앱에서 저장 실패 시 되돌림 [팀 확인 필요] |
| 재측정하기 | 그 별님을 대상으로 퀵 체온을 엶 | 저장 성공 시 업무 완료 | 저장 실패 시 업무는 남음 |
| 완료했어요 (메모 할 일) | 그 기록의 **업무만** 완료 | 할 일 −1. 읽음 확인은 그대로. 일정 자동 캘린더에 ✓ | 위와 같음 |
| 상세 | 기록 상세 시트 | **열어 본 것만으로는 읽음·완료가 바뀌지 않음** | — |

빈 상태: “안 읽은 기록이 없어요” / “남은 할 일이 없어요” / “오늘 기록이 아직 없어요”.

### 3-2. 퀵 체온 — “누구의 체온을 얼마로 기록하는가?”

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 반 칩 · 별님 동그라미 | 6반 명단. 오늘 기록이 있는 별님은 초록 테두리 | [원본 유지] |
| **기록 대상 띠** | “은하수자리 · 이서준 / 평소 37.1°”를 값 위에 항상 표시 | [신규 제안] |
| 큰 숫자 · − / + · 빠른 값 | 0.1° 단위, 범위 34.0~42.0 | [원본 유지] |
| 길게 눌러 기록 | 0.7초. 버튼 글자에 대상과 값이 함께 보임 | 길게 누르기 [원본 유지], 대상·값 표시 [신규 제안] |

**저장 상태 [신규 제안]**

| 상태 | 화면 | 누를 수 있는 것 |
|---|---|---|
| 입력 중 | 길게 눌러 기록 | 전부 |
| 저장 중 | “저장 중이에요. 다시 누르지 않아도 돼요” | **없음** (대상·값·닫기·기록 모두 잠김 → 중복 저장 방지) |
| 성공 | “✓ 이서준 38.4° · 10:06 기록됨 [이상]” + 무슨 일이 이어졌는지 한 줄 + [별님카드에서 보기] [다음 별님] | 두 버튼, 닫기 |
| 실패 | “저장하지 못했어요. 입력한 값과 대상은 그대로예요. 기록은 아직 남지 않았어요” + [다시 시도] [값 고치기] | 두 버튼, 값 조절 |

성공 뒤에 이어지는 일 (모두 `saveMeasurement` 그대로) [원본 유지]:

| 판정 | 일어나는 일 | 다른 화면 |
|---|---|---|
| 평소 | 기록만 | 현황판 표의 체온 |
| 주의 | 재측정 할 일(30분 뒤) 자동 생성 | 인수인계 할 일, 일정 “재측정·할 일” |
| 이상·저온 | 이상 대응이 열리고 간호 선생님 호출(관찰 중) | 현황판 붉은 행·타임라인, 호출함 새 호출, 일정 “이상 건” |
| 위험 | 긴급이 열리고 간호 선생님 호출(긴급) | 위와 같음 + 긴급 표시 |
| 열린 대응이 있을 때의 재측정 | 대응 기록에 추가, 열린 호출 대화에 활력징후 자동 첨부, 평소·주의면 회복 기록 | 호출함·의료진 포털 대화, 일정 ✓ |

- 서버 응답 전에는 “전송 완료”라고 쓰지 않습니다. 시연은 서버가 없으므로 성공 문구에 “실제 서버로 전송되지는 않았어요”를 함께 적습니다.
- 실제 앱에서 “기기에 저장됨”과 “서버에 올라감”을 따로 보일지, 실패의 기준은 **[팀 확인 필요]**.
- **읽음 확인은 체온을 저장해도 바뀌지 않습니다.** (내가 방금 쓴 기록은 처음부터 내가 읽은 것으로 표시 — 저장소 규칙 그대로.)

### 3-3. 별님카드 · 아카이브 — “평소와 무엇이 달라졌고 예전에는 어땠나?”

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 프로필 | 이름 · 성별·나이 · 담임 · 대응 중 표시 | [원본 유지] |
| 평소 체온 / 최근 체온 | 제공된 기준값, 최근 측정값·시각·기록자, 최근 추이 선 | [원본 유지] |
| 체온 기록하기 · 대응 기록 #n | 퀵 체온을 이 별님으로 엶 / 대응 기록으로 이동 | 연결 [신규 제안] |
| **일정 묶음** | 오늘 일정 + 앞으로 14일 안 별님 연결 일정, 최대 3건, 읽기 전용. PC 일정에서 넣으면 바로 보임 | [신규 제안] · [팀 확인 필요] |
| 검색 · 종류(모두/개인 기록/반 공지) · 기간(전체/오늘/7일) | 부분 일치 | [원본 유지] |
| 새 기록 n건 · 모두 확인 | 눌러야 읽음 처리 | [원본 유지] |
| 타임라인 | 날짜별. 기록 카드에는 읽음 확인·업무 두 칸, 평소 체온은 한 줄 | 두 칸 [신규 제안] |

빈 상태: “조건에 맞는 기록이 없어요” / “‘검색어’에 맞는 기록이 없어요” / “오늘과 앞으로 14일 안에 연결된 일정이 없어요”.

일정 묶음에서 정할 것 [팀 확인 필요]: 제목·메모의 민감한 내용을 모바일에 어디까지 보일지(일정 v2 §6-8), 누르면 어디로 갈지(시연은 이동 없음), 별님카드 시안(`ResidentTimeline`) 수정 주체.

### 3-4. 알림 · 대응 기록 — “간호 선생님이 확인했는가? 다음에 할 것은?”

| 표시 항목 | 내용 | 구분 |
|---|---|---|
| 알림 한 줄 | 반 · 별님 · 시각 · 내용 · “담당자 확인 ✓/전” · 업무 상태 | 목록 [원본 유지], 상태 칩 [신규 제안] |
| 대응 기록 | 상태 네 칸 + 의료 호출 진행 칩 + 시간순 이력 + [재측정 기록하기] | 네 칸 구분 [신규 제안] |

알림이 오는 때(시연): 간호 선생님이 확인했을 때, 재측정을 요청했을 때, 의료진 처방이 발행됐을 때, 긴급으로 바뀌었을 때. 내 담당 반 별님만 받습니다.

**상태 네 가지 [팀 확인 필요]**

| 상태 | 누가 바꾸나 | 시연에서 바뀌는 때 |
|---|---|---|
| 알림 읽음 | 나 | 알림을 눌렀을 때 (이것만 바뀜) |
| 담당자 확인 | 간호 선생님 | 호출함에서 [확인했어요]를 눌렀을 때. 어플에서는 읽기만 |
| 업무 (재측정) | 나 | 재측정 체온을 저장했을 때 |
| 대응 종료 | 기존 이상 대응 규칙 | 시연에서는 회복 기록 뒤 [대응 종료하기] (조건은 팀 확인 필요) |

처방·투약 내용과 케어팀 대화는 어플에 보이지 않습니다. “처방 발행됨” 같은 **결과 상태만** 봅니다.

## 4. 공통 규칙

- 읽음 확인·업무 상태는 인수인계·별님카드·상세·알림·현황판이 **하나의 원본**을 같이 봅니다.
- 체온 입력은 퀵 체온 한 곳뿐입니다. 기록을 지우는 동작은 없습니다. [원본 유지]
- 접근성: 모든 버튼은 실제 `<button>`, 저장 결과는 화면 읽기 프로그램에 바로 읽히도록 했고, 색만으로 구분하지 않고 글자를 함께 씁니다. 키보드는 Enter로 기록, Esc로 닫기.
