## 1. 실제 앱은 이미 서버와 이어져 있다 (코드로 확인한 사실)

| 항목 | 내용 | 근거 |
|---|---|---|
| 화면 | Flutter 웹 한 벌. 주소가 `/`이면 모바일, `/pc`이면 PC, `/doctor`이면 의료진 포털 | `screenKindOf`, `SETUP.md`의 접속 주소 표 |
| 빌드 | `flutter build web --release --dart-define=API_BASE_URL=/api/` | `SETUP.md` 4장, `lib/main.dart` |
| 서버 | Docker 안의 앱 서버 `:8093`이 `build/web`을 보여 주고 `/api/login`, `/api/state`(GET·PUT), `/api/photo`를 처리 | `backend/server.dart` |
| 저장 | 스냅샷 전체를 버전과 함께 PUT. 다른 화면이 먼저 저장했으면 409. 4초마다 서버 값을 다시 읽음. 요청은 8초 뒤 시간 초과 | `lib/server_app.dart` `_ServerStore` |
| 저장 실패 문구 | “저장하지 못했어요 …”, “서버 연결을 확인해 주세요. 기록을 저장하지 못했어요.” | 같은 파일 `_write` |

따라서 **서버와 이어진 모바일 앱은 팀 서버의 `http://10.14.11.221:8093/`** 입니다 (UNIST 네트워크 안). 통합 시연 앱(`web/mentoring/index.html`)은 흐름을 보여 주는 용도이고, 이 서버와는 연결돼 있지 않습니다.

## 3. 어플 개선 세 가지 — 지금 상태와 할 일

### A. 저장 상태 표시 (가장 먼저)

- **지금:** `lib/features/quick_temp/quick_temp_screen.dart`의 `_record()`가 기기 안에 기록하자마자 “체온 ○○° 기록이 완료되었습니다”를 띄웁니다. 서버로 올리는 일은 그 뒤에 `_ServerStore._write`에서 따로 진행되고, 실패하면 별도의 오류 문구가 나옵니다. 즉 **서버 응답 전에 “완료”가 먼저 보입니다.**
- **할 일:**
  1. 퀵 체온 결과 영역에 세 상태를 둡니다: 저장 중(버튼 잠금) → 저장됨 → 저장하지 못함(값·대상 유지, [다시 시도]).
  2. “저장 중”은 이미 있는 `repo.hasPendingSave`로 알 수 있습니다. “실패”는 지금 `saveError` 문구로만 나오므로, 퀵 체온 화면이 그 결과를 알 수 있게 하는 통로가 하나 필요합니다.
  3. 서버 없이 실행한 개발용(기기 안 저장)에서는 “기기에 저장됨”으로만 표시합니다.
- **팀장 확인이 필요한 것:** 2번의 통로는 `lib/core/` 또는 `server_app.dart`를 건드립니다 (`CLAUDE.md`: core를 바꿀 때는 팀에 먼저 알린다). 409가 났을 때 방금 입력한 체온을 자동으로 다시 저장할지, 사용자에게 다시 누르게 할지도 정해야 합니다. 지금 문구는 “방금 한 일을 한 번 더 해 주세요”입니다.

### B. 읽음 확인과 업무 완료 구분

- **지금:** `lib/features/handover/`에 [확인했어요], “담당 확인완료/미확인”, [재측정 완료], [완료]가 이미 따로 있습니다. 데이터도 `markRead`와 `completeTask`로 나뉘어 있습니다.
- **할 일:** 새 데이터 없이 **표시만** 정리합니다. 기록 카드마다 “읽음 확인 / 업무” 두 칸을 같은 자리에 두고, 별님카드 타임라인에도 같은 모양을 씁니다. 기록 상세를 열기만 했을 때 `markRead`가 불리는 곳이 있는지 점검합니다.

### C. 별님카드 일정 묶음

- **지금:** `lib/features/resident_card/`에 일정 표시가 없습니다. `CalendarEvent`(v1.01)에는 대상 별님 항목이 없고 반(`classId`)만 있습니다.
- **할 일:** 일정 v2의 저장 구조(일정 명세 7장)가 승인돼 “대상 별님”이 들어온 뒤에 만듭니다. 그 전에는 오늘의 반 일정만 읽기 전용으로 보여 줄 수 있습니다. 일정 v2 §7-5의 “예전 빌드가 새 항목을 지우는 문제”가 먼저 정리돼야 합니다.

### D. 알림 → 대응 기록 이동

- **지금:** `lib/features/alert_case/notice_center.dart`가 알림을 누르면 `openCaseDetail`로 갑니다. **이미 구현돼 있습니다.** 추가 작업 없음.

> A. 퀵 체온에서 서버 저장이 끝나기 전에 “기록이 완료되었습니다”가 먼저 뜨는 것을 고쳐 줘. 저장 중(버튼 잠금) → 저장됨 → 저장하지 못함(입력값과 대상 유지, 다시 시도) 세 상태를 보여 주고, 서버 없이 실행했을 때는 “기기에 저장됨”으로 표시해 줘. `lib/core/`나 `server_app.dart`를 바꿔야 하면 바꾸기 전에 무엇을 왜 바꾸는지 먼저 알려 줘.
> B. 인수인계 카드와 별님카드 타임라인에 “읽음 확인 / 업무” 두 칸을 같은 모양으로 보여 줘. 새 데이터는 만들지 말고 `markRead`와 `completeTask`의 지금 상태를 그대로 써 줘. 기록 상세를 열기만 해도 읽음 처리되는 곳이 있으면 알려 줘.

> 판정 기준, 재측정 간격, 투약 관련 코드는 건드리지 마. PC 화면과 서버 API·DB 구조도 바꾸지 마. `flutter analyze`와 `flutter test`를 돌리고, 360×640에서 넘치지 않는지 위젯 테스트를 추가해 줘. 가능하면 서버를 켜고 체온 저장 → `/pc` 현황판 반영 → 새로고침 뒤 유지 → 서버를 끈 상태에서 저장 실패까지 확인해 줘. 확인하지 못한 것은 못 했다고 적어 줘. 마지막에 바꾼 파일, 검수 결과, 팀장에게 물어볼 것을 정리해 줘.
