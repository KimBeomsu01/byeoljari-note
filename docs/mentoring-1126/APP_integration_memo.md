## 1. 다섯 화면이 함께 쓰는 데이터

| 자료 (저장소 이름) | 만드는 화면 | 읽는 화면 |
|---|---|---|
| 측정 + 저장 시점 판정 (`Measurement`, `judge`) | 어플 퀵 체온 | 현황판 표·카드, 호출함 건강기록·추이, 의료진 포털 현재 체온, 어플 별님카드 |
| 이상 건 (`Case`) | 체온 저장 시 자동 | 현황판 붉은 행·카드 ②, 어플 대응 기록, 일정 “이상 건” |
| 의료 호출 (`MedicalCall`) | 체온 저장 시 자동 | 호출함 목록, (보낸 뒤) 의료진 포털, 현황판 대응 현황 칩 |
| 케어팀 대화 (`CareMessage`) | 호출함, 의료진 포털, 활력징후 자동 첨부 | 호출함과 의료진 포털이 **같은 메시지**를 봄 |
| 담당자 확인 (`acknowledge`) | 호출함 | 어플 알림·대응 기록, 현황판 타임라인 |
| 재측정 예정 (`Case.remeasureAt`) | 호출함 | 어플 할 일·알림, 일정 “재측정·할 일”, 현황판 칩 |
| 화상 진료 예약 (`MedicalCall.videoAt`) | 의료진 포털 | 일정 “진료·의료 호출”, 호출함 대화, 현황판 카드 ③ |
| 전자처방전 (`Prescription`) | 의료진 포털 | 호출함 처방 기록, 현황판 타임라인·칩, 어플에는 “발행됨”만 |
| 인수인계 기록·읽음·할 일 (`Entry`, `Task`) | 어플 | 현황판 인계 확인율·공지, 일정 “재측정·할 일” |
| 일정 (`CalendarEvent` + 대상 별님) | 일정 | 어플 별님카드 일정 묶음 (읽기 전용) |

어플이 새로 만든 저장 항목은 없습니다.

## 2. 기존 유지 / 추가 제안 / 팀 확인 필요

### 기존 유지
- 판정·저장·호출 규칙 전부 (`judgment.dart`, `repository.dart`).
- 어플 하단 메뉴 `인수인계 · 퀵 체온 · 별님카드` (`v1.01`), 퀵 체온 입력 방식, 별님카드 구성.
- 현황판의 카드 4장·표 7열·생활관 타일·타임라인·“행을 누르면 호출함” (BOARD.md 3장, 4-1).
- 호출함 3단(목록·케어팀 대화·종합 건강기록), 의료진 포털 3단(호출함·별님별 채팅·작성 패널), “보낸 호출만 의료진 쪽에 생김” (doctor_portal_spec 4장).
- 일정의 자동 캘린더는 저장하지 않고 읽기만, 삭제 대신 취소, 별님을 붙이면 반 고정 (일정 v2 §6-7, §6-4, §6-8).
- 투약 용량 계산·추천 없음, 기록 삭제 없음.

### 추가 제안 (어플)
1. 저장 상태: 저장 중 잠금 · 성공 문구에 대상·값·시각·판정과 이어진 일 · 실패 시 입력값 유지와 다시 시도.
2. 별님별 연결: 인수인계 이름 → 별님카드, 저장 성공 → 같은 별님카드, 알림 → 대응 기록.
3. 읽음 확인과 업무 완료를 두 칸으로 분리. 대응 기록에는 상태 네 칸.
4. 별님카드 일정 묶음 (일정 v2 §6-13 안).

## 3. 시연을 위해 정한 것 (실제 화면과 다를 수 있음)

| 통합 시연에서 | 근거·주의 |
|---|---|
| 호출함의 [확인했어요] 버튼 | `acknowledge()`를 간호 선생님 이름으로 부름. 실제 PC 화면에 같은 버튼이 있는지는 확인하지 못함 |
| 호출함의 [재측정 요청 (30분 뒤)] | `scheduleRemeasure`와 기존 화면의 30분 값을 사용. PC 호출함에 이 버튼이 있는지는 미확인 |
| 화상 진료 시각 | 다음 10분 단위 + 30분으로 고정. 실제는 시각을 고르는 방식일 것 |
| 처방 발행 조건 (상병명 + 약 1개) | 상문 님 시안의 시연용 조건 그대로 |
| [시연용 가상 문구 채우기] | 실제 약 이름·용량을 쓰지 않으려고 “가상약 A” 문구를 넣음 |
| 대응 종료 | 회복 기록 뒤 어플에서 누르게 함. 실제 조건은 기존 이상 대응 규칙을 따라야 함 |
| 현황판 “인계 확인율” | 오늘 인수인계 기록 중 어플에서 읽음 확인한 비율. 실제 카드는 교대조 서명 기준으로 보임 |
| 현황판에서 뺀 것 | 인계 리포트·명부·이상 알림 이력·긴급 방송 버튼과 모달, 결재 대기 |
| 호출함에서 뺀 것 | 파일 첨부, 주의사항 편집, 혈압·맥박 입력 |
| 의료진 포털에서 뺀 것 | 9장 제안(호출 한눈에, 발행 전 확인, 정렬·검색, 문구 저장) |
| 일정에서 뺀 것 | 주·일 보기, 반복, 검색, 엑셀, 근무조 띠, 알림 칸. 월 보기와 자동 캘린더·별님 연결만 |
| “현재 위치 및 일과” | 시각에 따라 자유 시간·점심·등교만 바뀜. 실제는 일과 데이터 |

빠진 기능은 각 담당의 원본 시안·명세(`originals/`)에 그대로 있습니다. 통합 시연 앱 화면에는 개발 담당자 이름을 표시하지 않습니다.

## 4. 실제로 검수한 내용

2026-11-26, `index.html`을 Chrome(헤드리스) 1600×950에서 열어 자동으로 눌러 확인했습니다. 46개 항목 모두 통과, 콘솔 오류 0건.

| 구간 | 확인한 것 |
|---|---|
| 처음 상태 | 현황판 1건 활성(박승민), 의료진 열린 호출 0건 |
| 어플 저장 | 대상 띠 표시, 저장 중 잠금과 중복 저장 차단, 실패 시 기록 없음·입력값 유지, 다시 시도 성공, “서버 미전송” 문구 |
| 어플 → 현황판 | 2건 활성, 이서준 행이 맨 위, 타임라인에 호출 접수 |
| 현황판 → 호출함 | 행 클릭으로 이동·호출 선택·읽음, 대화에 활력징후 자동 첨부 |

| 의료진 포털 | 보낸 호출만 나타남, 간호 선생님 메시지가 같게 보임, 발행 버튼 잠금 조건, 화상 진료 예약, 처방 발행 |

## 5. 통합 전에 꼭 맞출 것

1. **구버전 저장 호환성 (일정 v2 §7-5의 3번).** 예전 빌드가 스냅샷 전체를 다시 올리면 반복·취소·별님 연결 같은 새 일정 항목이 사라질 수 있습니다. 어플을 따로 배포하면 “예전 설치형 앱”이 그 경우가 됩니다. 배포 전에 서버의 최소 빌드 확인 또는 동시 배포 중 하나를 정해야 합니다.
2. **기준 브랜치.** `v1.01`(2026-11-20)이 최신 작업이고 `main`(2026-11-13)은 그 전 디자인입니다. 공개 시연판은 `main`을 배포합니다.
3. **네트워크.** 서버는 UNIST 내부망에서만 열립니다. 바깥에서 안 보이는 것을 화면 오류로 보지 않고, 공개 터널로 우회하지 않습니다.
