# 별자리노트 — 의료진 협진 포털 (의료진 호출함) 기능 명세 (초안)

- 작성: 진모(현황판 담당) · 2026-11-25
- 용도: 의료호출 담당(상문/용태)의 간호사 쪽 명세와 **안 꼬이게** 맞추기 위한 의료진 쪽 정리. 용태 님이 통합할 때 대조용.
- 가짜 데이터만 씁니다(별님 이름·체온·처방번호 모두 가상).
- 태그: **[결정]** 실제 화면에서 직접 확인 · **[확인 필요]** 확인 못 했거나 팀이 정할 것 · **[제안]**

## 0. 확인 범위

- 주소 `/doctor`(의료진 협진 포털)에 의료진 테스트 계정으로 로그인한 화면을 직접 눌러서 봤습니다. **로그인은 제가 입력하지 않았고 진모 님이 직접 했습니다.**
- 눌러본 것: 호출 카드 3개(열린 2, 끝낸 1), [열린 호출][끝낸 호출] 탭, 별님별 채팅 펼치기, [투약 이력] 창, 오른쪽 작성 패널 스크롤.
- **누르지 않은 것**(보내거나 발행하는 버튼): 채팅 [전송], [화상 진료 예약/화상 진료], [+ 바이탈 첨부], [+ 처방약 추가], [전자서명 완료 및 전자처방전 발행·전송]. 이 버튼들의 동작은 모두 **[확인 필요]**.
- 간호사 쪽(`/pc` 의료 호출함)도 같은 날 눌러보며 대조했습니다(5장). 그쪽 기능명세 본문은 받지 못해서 **화면 기준**으로만 대조했습니다.

## 1. 한눈에

의료진 협진 포털은 **혜진원에서 보낸 호출을 받아 채팅으로 확인하고, 비대면 진단서와 전자처방전을 작성·발행**하는 의료진 전용 화면입니다. PC 3단입니다.

| 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|
| 호출함: 열린 호출 / 끝낸 호출 | 별님별 채팅 (펼치기) | 비대면 진단서 및 전자처방전 작성 |

사이드바에는 의료 호출함 아이콘 하나뿐입니다(현황판·일정 메뉴 없음).

## 2. 소유와 경계

| 영역 | 소유 | 비고 |
|---|---|---|
| 간호사 쪽 의료 호출함(보내기·완료·채팅) | 의료호출 | 이 문서는 건드리지 않음 |
| **의료진 포털 화면 (이 문서)** | 의료호출 계열 | 간호사 쪽과 같은 호출·채팅·처방 자료를 다른 눈으로 봄 |
| 현황판 | 현황판 | 의료진 포털을 열지 않음. 호출 상태 칩·타임라인(처방전 수신)만 읽기 |
| 이상 대응(확인·단계·종료) | 이상 대응 | 의료진 포털에서 하지 않음 |

**[결정]** 의료진 포털은 간호사 쪽과 **같은 호출·채팅·처방 자료**를 쓰고, 새 저장을 만들지 않습니다.

## 3. 화면 구성 (직접 확인)

**상단 바**: "별자리노트 / 의료진 전용 협진 포털 / 실시간 임상 관리", 시설 칩(울산 혜진원 장애인거주시설), 로그인 세션 남은 시간, 사용자(예: 강다혜 촉탁의 (원장) · 내과·외과 · 촉탁 · 외래전담).

**호출함 (왼쪽)**: 머리 "호출함 · 협진 기관에서 보낸 호출". 탭 [열린 호출 n][끝낸 호출 n]. 카드 한 장: 보낸 기관 칩(혜진원), 시각(11.20 (금) 10:11), 이름 (성별 · 만 나이) · 생활관 호실, 긴급 칩 또는 "일반 의뢰" 칩 + 체온, 호출 메시지, "○○ 수석간호사 보냄". 선택된 카드는 파란 테두리.

**별님별 채팅 (가운데)**: 머리 "별님별 채팅 · 혜진원 별님마다 대화가 따로 있어요. 눌러서 펼쳐요." 별님마다 한 줄(아바타, 이름 별님, 반·호실, 마지막 메시지, 시각). 펼치면: 칩 3개 [화상 진료 …][+ 바이탈 첨부][투약 이력] → 대화 → 입력창 "○○ 별님 건으로 보낼 메시지" + [전송].
- 대화에 섞여 나오는 것: 내 메시지(파랑), 상대 메시지(이름·시각), 시스템 안내(예: "촉탁의 강다혜 님이 비대면 진단 대기실에 입장하셨습니다", "전자처방전을 발행했어요 (Rx#…)"), **시스템 자동 첨부 · 실시간 활력징후 카드**(거주인, 체온, 평소 기저체온, 측정 시각·기록자).

**비대면 진단서 및 전자처방전 작성 (오른쪽)**: 머리 오른쪽에 상태 칩 **[진단 작성중] 또는 [발행 완료]**. 카드 3개 + 바닥.
1. 별님 카드: 이름, (성별 · 나이), 생활관·기록번호, **현재 체온**, "처방 주의: …"(예: 페니실린계·세파계 항생제 절대 금기 / 등록된 금기 없음).
2. 진단 상병 및 질병코드 (KCD-8): 코드·상병명·[주상병]. 진료 소견 및 원격 지도사항(작성중이면 입력칸 + "실시간 동기화", 발행 뒤에는 "발행됨 · 고칠 수 없음").
3. 비대면 처방의약품 지정 n개 품목: 약 이름·용법·양 입력(의사가 쓴 그대로). [+ 처방약 추가]. 안내 "의사가 쓴 글 그대로 저장돼요. 앱은 투약 용량을 계산하거나 추천하지 않아요."
4. 바닥: "의사 전자서명: ○○ 촉탁의 (원장)" + (발행 전) "발행하면 고칠 수 없어요" / (발행 후) "✔ 서명 완료". 버튼 발행 전 **[전자서명 완료 및 전자처방전 발행·전송]**, 발행 후 **[발행 완료 · Rx#번호 · 시각]**(눌리지 않는 모양).

**투약 이력 창**: "○○ 투약 이력" + 안내(의료진이 쓴 글 그대로, 용량 계산 안 함). 구역: 상시 복약 · 필요시 투약 지시 · 전자처방전 n건(발행됨 + 상병 + 처방 품목) · 이상 대응 투약 기록 n건. [닫기].

## 4. 상태 규칙 [결정]

| 항목 | 규칙 |
|---|---|
| 열린 호출 | 간호사가 의료진에게 **보낸** 호출만 나타남. 아직 안 보낸 호출은 의료진 쪽에 없음 |
| 끝낸 호출 | 간호사가 [완료]한 호출로 보임(확인 필요: 완료 주체) |
| 호출 선택 | 카드를 누르면 가운데 해당 별님 채팅이 펼쳐지고 오른쪽 패널이 그 별님 것으로 바뀜 |
| 작성 상태 | 처방 전 [진단 작성중], 발행 뒤 [발행 완료]. 발행하면 고칠 수 없음 |
| 용량 | 앱은 약 용량을 계산·추천하지 않고 의사가 쓴 글 그대로 보여줌 (통합명세 "투약 용량 계산 없음"과 같음) |
| 긴급 표시 | 호출 카드에 [긴급] 칩 + 붉은 체온. 일반은 "일반 의뢰" 회색 칩 |

## 5. 간호사 쪽(의료 호출함)과 대조 — 같은 자료, 다른 눈

| 항목 | 간호사 쪽 (`/pc` 의료 호출함) | 의료진 쪽 (`/doctor`) | 판단 |
|---|---|---|---|
| 호출 목록 건수 | 열린 호출 6 · 끝낸 호출 16 | 열린 호출 2 · 끝낸 호출 1 | 간호사가 [의료진에게 보내기]를 눌러야 의료진 쪽에 생김. 임유나 호출은 "아직 의료진에게 보내지 않았어요"라서 의료진 쪽에 없음. **같은 규칙으로 정리 [결정]**. 끝낸 호출 16 vs 1은 이유 모름 [확인 필요] |
| 카드 문구 | "강다혜 촉탁의 (원장)에게 보냄 · 10:11" | "박소연 수석간호사 보냄" | 보낸 쪽/받는 쪽 시점만 다름. 충돌 없음 |
| 카드 버튼 | [의료진에게 보내기][채팅 보기][✓ 완료] | 없음(카드를 누르면 선택만) | 소유 다름. 충돌 없음 |
| 채팅 구조 | **의료진별** 채팅 목록 안에서 "보낼 별님"을 고름 | **별님별** 채팅 목록 | 같은 대화를 다른 축으로 묶음. 같은 메시지가 양쪽에 같게 보여야 함 [확인 필요: 실제로 같은 데이터인지] |
| 채팅 칩 | [화상 진료 11/20 10:20][+ 바이탈 첨부][투약 이력] | 같은 3개 | 일치 |
| 처방 기록 | 오른쪽 탭 "비대면 진단·처방 기록"에 발행된 전자처방전이 쌓임(같은 Rx#88124) | 오른쪽 작성 패널의 발행 완료 화면 | 의료진이 발행하면 간호사 쪽에 나타나는 흐름으로 보임 |
| 상태 이름 | 종합 건강기록 안 처방 프리뷰 "진료 대기", 기록 카드 "발행됨" | 작성 패널 "진단 작성중", "발행 완료" | 용어가 둘로 나뉨 [확인 필요: 통일 여부] |
| 긴급 표시 | 이서준 카드 [긴급] 칩 | 이서준 카드 [긴급] 칩 | 두 화면 일치. **그런데 PC03 디자인 명세 4.3은 "긴급 구분을 없앴다"** → 명세와 화면이 어긋남 [확인 필요] |
| 현재 체온 | 별님 현재 값 | 호출 시점 값이 아니라 **현재 값**으로 보임(11/8 끝낸 호출에도 38.2°C) | 의료진이 옛 호출에서 현재 값을 보게 됨 [확인 필요] |
| 용어 | 별님(거주인 혼용) | 별님 | 의료진 쪽은 별님으로 통일되어 있음 |

## 6. 현황판과의 관계

- 현황판은 의료진 포털을 열지 않고, 호출 상태 칩(발송완료·연결됨·관찰 중)과 타임라인 카드("비대면 협진 완료 · 처방전 수신 Rx#…")만 **읽어서 보여줍니다**.
- 현황판의 "의료진 호출 대기"는 간호사 쪽 6건 기준이고, 의료진 쪽 열린 호출(보낸 것만)과 숫자가 다를 수 있습니다. 같은 자료로 같은 말을 쓰도록 의료호출 담당과 맞출 것 [확인 필요].

## 7. 확인 필요 모음

1. [전송][화상 진료][바이탈 첨부][처방약 추가][발행·전송]의 실제 동작(누구에게 어떤 알림이 가는지 포함)
2. 호출이 "끝남"이 되는 주체와 조건, 끝낸 호출 16 vs 1
3. 간호사·의료진 채팅이 같은 데이터인지, 메시지 시각 순서(예: 13:47 메시지가 10:19 뒤에 나옴)
4. [긴급] 칩을 둘지 (PC03 명세와 화면 불일치)
5. 상태 이름 통일(진료 대기 / 진단 작성중, 발행됨 / 발행 완료)
6. 끝낸 호출에서 "현재 체온"이 현재 값인지 호출 시점 값인지
7. 의료진 계정 권한(처방 쓰기는 촉탁의만인지, 다른 의료진은 보기만인지)
8. 투약 이력 창 정확한 문구와 "이상 대응 투약 기록"의 출처

## 8. 시안 HTML 안내

`별자리노트_의료진포털_화면시안.html`은 3장 화면을 그대로 옮긴 것에, **파란 "제안" 태그가 붙은 부분만** 더한 것입니다. 태그가 없는 곳은 실제 화면 그대로입니다. 눌러서 움직이는 것: 호출 카드 선택, [열린/끝낸 호출] 탭, 별님 채팅 펼치기, [투약 이력] 창, 그리고 아래 9장 제안(검색·정렬·문구 저장). 채팅 [전송]은 Enter 또는 버튼으로 내 말풍선(파랑)을 붙이고, 마지막 메시지 줄과 시각을 바꾸며, 입력칸을 비웁니다. 시안 안에서만 움직이며(새로고침하면 사라짐) 실제 사이트의 [전송] 동작은 누르지 않아 확인하지 못했습니다 [확인 필요: 누구에게 어떤 알림이 가는지]. 나머지 버튼도 시안 안에서는 움직입니다(새로고침하면 처음으로 돌아감). **실제 사이트에서는 누르지 않은 버튼이라, 아래 동작은 시안을 위해 정한 것이고 실제와 다를 수 있습니다 [확인 필요]**:
- [화상 진료]: 대화에 "촉탁의 강다혜 님이 비대면 진단 대기실에 입장하셨습니다" 안내가 붙음(실제 이서준 대화에서 본 문구).
- [+ 바이탈 첨부]: 대화에 "시스템 자동 첨부 · 실시간 활력징후" 카드가 붙음(별님 현재 체온, 측정 시각).
- 작성 중 패널: 질병코드·상병명·소견·처방약(약 이름·용법·양)을 직접 적고, [+ 처방약 추가]·[✕]로 줄을 늘리고 줄임.
- [전자서명 완료 및 전자처방전 발행·전송]: 상병명과 처방약 1개 이상이 있어야 눌림(이 조건은 시안용). 누르면 [발행 완료]·Rx#·시각이 붙고 대화에 "전자처방전을 발행했어요" 안내가 생기며, 소견은 고칠 수 없게 바뀜. 간호사 쪽으로 가는 알림은 만들지 않음.
- 로그인 세션 남은 시간은 줄어듦.
- 움직이지 않는 것: 왼쪽 로고·메뉴·아바타, 상단 칩(실제 화면에서도 누르는 용도를 확인하지 못함).

## 9. 제안 (실제 화면에 없음 · 모두 [제안])

원칙: 앱이 의학적 판단·평가·용량을 만들지 않습니다. 이미 있는 기록과 간호사·의사가 쓴 글을 **모아 보여주거나 정렬**하는 것만 제안합니다.

| # | 제안 | 시안 위치 | 근거 | 막아야 할 것 |
|---|---|---|---|---|
| P0 | **호출 한눈에 (상황·배경·요청)**: 오른쪽 맨 위에 호출 때 간호사가 보낸 글(상황·요청)과 등록 기록(상시 복약·필요시 지시·금기)을 한 카드로 모음 | 오른쪽 패널 위 | SBAR는 상황·배경·평가·요청 순서로 전하는 틀(AHRQ). 평가(A)는 간호사가 쓴 글이 있을 때만 | 앱이 평가·권고를 만들어 붙이지 않음 |
| P0 | **발행 전 확인**: 금기·상시 복약·필요시 지시·처방 품목 수를 발행 버튼 위에 한곳에 모음 | 오른쪽 패널, 작성 중일 때만 | 경고는 환자 상태에 맞을 때만, 그리고 "경고가 없으니 안전"이라는 과신(자동화 편향)을 막아야 함(Baysari 외) | 맞다/틀리다 판정, 용량 계산·추천 없음. 팝업으로 막지 않음 |
| P1 | **내 답 대기** 칩: 열린 호출 중 내가 아직 답(처방·메시지)하지 않은 건 표시 | 호출 카드 | 새 것과 처리한 것을 구분하고 처리 전까지 사라지지 않게(AMA 인박스 5가지) | 기준은 "의사 메시지·처방 없음"으로만. 시간 경과로 긴급 판단 안 함 |
| P1 | **정렬 [긴급 먼저] · 별님 이름 검색** | 호출함 위 | 우선순위로 정렬·거르기(AMA) | 기본은 실제 화면대로 시각 순서. [긴급] 칩 자체는 5장 충돌 정리 전까지 그대로 |
| P1 | **접수 → 발행 소요 시간**(예: 10:11 → 14:35 · 4시간 24분) | 끝낸 호출 아래쪽 | 처리 흐름 파악. 이미 있는 두 시각의 차이일 뿐 | 지연 경고·평가로 쓰지 않음 |
| P2 | **자주 쓰는 문구**: 의사가 쓴 소견을 문구로 저장하고 눌러서 불러옴. 처음엔 비어 있음 | 진료 소견 칸 아래 | 메시지 템플릿으로 반복 입력 줄이기(AMA) | 앱이 만든 문구는 넣지 않음(의사가 쓴 그대로). 시안은 새로고침하면 사라짐. 실제로 저장하려면 의사 계정별 저장 필요 [확인 필요] |
| P2 | (시안에 없음) 소견의 "1시간 후 재측정 요망"을 **간호사 쪽 할 일로 연결** | — | 현황판 인계 할 일, 일정 v2와 이어짐 | 간호사·일정 담당과 합의 전에는 만들지 않음 [확인 필요] |
| P2 | (시안에 없음) 발행하면 **간호사 호출 카드에 "발행됨" 표시와 알림** | — | 처방 발행 뒤 간호사가 바로 알아야 함 | 실제 알림 동작은 미확인(7장 1번) |

## 9-1. 제안과 간호사 쪽(의료 호출함)의 호환

간호사 화면과 직접 나란히 눌러 본 것은 아니고, 5장 대조 결과를 기준으로 본 것입니다.

**안 꼬이는 것 (의사 화면 안에서만 움직이거나, 이미 있는 값만 쓰는 제안)**

| 제안 | 이유 |
|---|---|
| 호출 한눈에 | 간호사가 보낸 글·시각·체온·등록 금기와 복약을 그대로 모음. 새 데이터 없음 |
| 접수→발행 소요 시간 | 간호사 카드의 "보냄 시각"과 발행 시각(Rx#) 두 값의 차이일 뿐 |
| 이름 검색, [긴급 먼저] 정렬 | 의사 화면 안에서만 동작. 데이터를 바꾸지 않음 |
| 자주 쓰는 문구, 발행 전 확인 | 의사 화면 안에서만 쓰임. 간호사 쪽으로 보내는 것 없음 |
| 용량 | 용량 계산·추천 없음. 팀 규칙과 같음 |

**아직 맞춰야 하는 것 [확인 필요]**

| 항목 | 무엇이 걸리는가 | 정할 것 |
|---|---|---|
| 내 답 대기 칩 | 의사 쪽에서만 쓰는 말. 간호사 쪽 "진료 대기"와 같은 상태인지 모름. 이름이 다르면 같은 호출이 양쪽에서 다른 말로 보임 | 상태 이름 통일(7장 5번)과 함께 정함 |
| [긴급] 칩, [긴급 먼저] 정렬 | PC03 명세는 "긴급 구분을 없앴다"인데 실제 간호사·의사 화면에는 [긴급] 칩이 있음 | 칩 유지 여부(7장 4번). 칩이 없어지면 정렬 제안도 빼야 함 |
| 발행 후 간호사 알림, 재측정을 할 일로 잇기 | 간호사 쪽 화면과 알림이 바뀌어야 하는 안. 시안에는 넣지 않음 | 간호사·일정 담당과 합의, 실제 알림 동작 확인(7장 1번) |
| 끝낸 호출 수 차이 | 간호사 16 vs 의사 1(7장 2번). 의사 쪽엔 끝낸 호출이 적어 소요 시간이 표시될 호출도 적음 | 끝낸 호출 기준 |

합칠 때 먼저 확인할 것: "내 답 대기"의 이름, [긴급] 칩.

## 10. 참고한 레퍼런스

- AHRQ TeamSTEPPS, [SBAR](https://www.ahrq.gov/teamstepps-program/curriculum/communication/tools/sbar.html): 상황·배경·평가·요청 순서로 전하고, 필요한 부분만 골라 쓸 수 있음 → P0 호출 한눈에
- AMA, [Physicians weigh in: 5 keys to fixing the EHR inbox](https://www.ama-assn.org/practice-management/digital-health/physicians-weigh-5-keys-fixing-ehr-inbox): 우선순위 정렬·필터, 새 것과 처리한 것 구분, 처리 전까지 안 사라지게, 메시지 템플릿, 중복·불필요 정보 줄이기 → P1 내 답 대기·정렬·검색, P2 문구
- Baysari 외, [전자처방 의사결정 지원 설계 고찰(NPS MedicineWise 자료)](https://www.nps.org.au/assets/p136-Baysari-Raban.pdf): 경고 피로를 줄이려면 환자·처방에 맞는 경고만 띄우고, 경고가 없다고 안전하다고 믿는 자동화 편향을 경계 → P0 발행 전 확인(경고 대신 사실을 모아 보여줌)
- 확인하지 못한 것: 전자처방 경고 UI 논문 일부(PMC 접속 제한)와 비대면 진료 기록 필수 항목(원문에 없음). 이 부분은 근거 없이 넣지 않았습니다.
